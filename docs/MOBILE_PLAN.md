# DECOY 모바일(안드로이드) 계획 — M10~M14

PC판은 그대로 두고, 휴대폰 브라우저와 안드로이드 앱(PWA → PWABuilder TWA)으로도 할 수 있게 만든다. PC와 휴대폰은 같은 방에서 함께 한다. 목표는 **구글 플레이에 비공개 테스트로 올릴 수 있는 상태**까지이고, 계정 · 결제 · 서명 키가 필요한 일은 `docs/PLAY_STORE_GUIDE.md`로 넘긴다.

지키는 것:

- **서버 판정 규칙과 입력 메시지 형식은 바꾸지 않는다.** 터치는 지금의 `InputFrame {seq, mx, my, aim, held, pressed}`를 그대로 만든다. 서버는 PC인지 휴대폰인지 모른다
- PC 화면(1920×1080 논리 해상도, 키보드 · 마우스)은 그대로다. 터치 화면 요소는 터치 기기에서만 만든다
- 수치는 `config/balance.json`, 문구는 `client/src/data/storyText.ts` + `docs/STORY_TEXT.md`, 메시지 타입은 `shared/src/types.ts` 한 곳
- 콘솔 에러 · 경고 0, 규칙마다 단위 테스트, 마일스톤마다 자동 검증 통과 후 병합

## 0. 지금 구조에서 모바일에 걸리는 것

코드를 영역별로 읽고 정리한 사실이다(경로는 저장소 기준).

| 영역 | 지금 | 모바일에서 생기는 일 |
|---|---|---|
| 입력 | `client/src/input.ts`가 키보드 · 마우스를 읽어 1/30초마다 `InputFrame`을 만든다(`GameScene.ts` 4ms 타이머). 괴물 `aim`은 커서 위치가 아니라 **목표 절대 각도**다. 서버는 구조(`RESCUE`)만 `held`로, 나머지 버튼은 `pressed`로 처리한다 | 조이스틱 각도를 `aim`에 그대로 넣으면 된다(540°/초 회전 상한도 그대로 걸린다). 그런데 지금은 **캔버스를 터치하면 괴물 공격이 나가고**(`input.ts` pointerdown이 pointerType을 안 봄), **조준이 마지막 손가락을 따라간다**(`GameScene.aimTarget`이 Phaser activePointer 사용) |
| 이동 크기 | 서버는 길이 1을 넘는 이동 벡터만 줄인다(`shared/src/movement.ts`). PC는 8방향 · 길이 1 | 조이스틱을 반만 밀면 느리게 걷는다. 최고 속도를 PC와 맞추려면 데드존 밖에서 길이 1로 보낸다 |
| 괴물 공격 방향 | 서버는 공격을 회전보다 먼저 처리하고, 공격 방향은 그 순간의 `face`다(`game.ts` 처리 순서, `combat.ts`) | "놓으면 공격"을 그대로 하면 스틱을 크게 휘두르고 바로 놓을 때 예전 방향으로 공격이 나간다 → 클라이언트가 발사를 잠깐 늦춘다(아래 M10) |
| 화면 | 논리 1920×1080을 FIT으로 줄인다. HUD는 전부 Phaser 캔버스 안, 로비 · 결과는 HTML | 844×390 휴대폰에서 글자가 **5~11 CSS px**, 미니맵 80×53px, 결과 화면은 **위쪽이 잘리고 스크롤도 안 된다**(`style.css` `.result`) |
| 기본 동작 | viewport에 `maximum-scale` · `viewport-fit` 없음. `touch-action` · `user-select` · `overscroll-behavior` · safe-area 규칙 0건 | 핀치 확대, 당겨서 새로고침, 길게 눌러 선택이 다 된다 |
| 연결 | 로비 홈은 **서버에 연결된 뒤에만** 그린다(`app.ts` onOpen). 재연결은 1초 고정 무한 반복. pageshow · online · freeze 처리 없음 | 서버가 잠들었거나 오프라인이면 누를 버튼이 없다. 화면이 꺼졌다 켜질 때 반쯤 열린 소켓이면 멈춘 채로 남을 수 있다 |
| 서비스 워커 | `client/public/sw.js`는 페이지 이동만 가로채고 `wake.html`만 캐시한다. "게임 코드는 캐시하지 않는다"(DECISIONS) | **오프라인에서 앱을 열 수 없다.** "봇과 연습"을 오프라인으로 하려면 앱 셸(index.html · JS · CSS)을 캐시해야 한다 |
| 시뮬레이션 | `server/src`(game, systems, interest, room, sim, botBrains, pathfind)에 있다. Node 의존은 **`node:crypto` 두 곳뿐**(interest · room). 브라우저용으로 묶으면 서버 코드 약 24KB(min) 늘어난다 | 기기 안에서 그대로 돌릴 수 있다. `Room`까지 돌리면 로비 · 판 · 결과 흐름과 정보 차단(`buildSnapshot`)을 그대로 쓴다 |
| 봇 | `?bots=1` 봇은 개발용: **괴물 봇은 공격하지 않고** 생존자 봇은 순찰만 한다. 루프백 WebSocket으로 붙는다 | 빠른 매칭 · 봇과 연습에 그대로 쓰면 판이 시간 초과로만 끝난다 → 실전용 봇 두뇌가 필요하다 |
| 길찾기 | `server/src/pathfind.ts`: 경로를 못 찾으면 **매 틱 A\*를 다시 돈다.** 봇 4명 판에서 틱 시간의 약 97% | 휴대폰 메인 스레드와 Render 무료 CPU(0.1개)에 그대로 부담 |
| 서버 경로 | 없는 경로는 모두 `index.html` 200(`static.ts`). `.webmanifest` MIME 없음. 압축 없음(번들 1.28MB, gzip이면 약 350KB) | `/privacy`, `/.well-known/assetlinks.json`은 명시 라우트가 필요하다. 첫 로딩이 모바일 데이터로 무겁다 |
| 기기 저장 | sessionStorage `decoy:seat:<방>`, localStorage `decoy:seats` · `decoy:name`, sessionStorage `decoy-wake-reloads`, Cache `decoy-wake-v1`. 쿠키 · 분석 · 외부 요청 없음 | 개인정보처리방침의 근거. 모바일 작업으로 키가 늘어난다 |
| 서버 로그 | 판 시작 때 `방 CODE 판 시작 (닉네임:역할, …)`을 남긴다(`room.ts`) | Render 로그에 닉네임이 남는다 → 처리방침 · 데이터 보안 답변이 복잡해진다 |
| 로고 | `docs/images/logo_decoy.png`는 **213×213** | 192 · 512 아이콘과 스토어 512 아이콘은 확대본이라 흐려진다 |
| 저장소 · CI | 저장소는 **private**(문서에는 '공개'로 적혀 있음). 브랜치 보호 없음. CI 4작업, 한 번에 약 6분. `main` 병합 → Render 자동 배포 | 병합 전에 4작업 성공을 직접 확인해야 한다. **병합할 때마다 서버가 다시 떠서 진행 중인 방이 사라진다.** Actions 시간이 과금 대상(무료 한도 안) |

## 1. 빠졌거나 순서를 바꾸자고 제안하는 것

요청한 M10~M14 구성은 그대로 두고, 아래를 더하거나 옮긴다. "진행해"라고 하면 이 표대로 간다.

| # | 제안 | 이유 | 위치 |
|---|---|---|---|
| 1 | **앱 셸 캐시(서비스 워커)를 M13에서 M12로 당긴다.** M13에는 manifest · 아이콘 · assetlinks · TWA 준비만 남긴다 | 앱 셸을 캐시하지 않으면 서버가 잠들었거나 오프라인일 때 앱을 새로 열면 깨우기 화면(`wake.html`)만 나와서 "봇과 연습"을 시작할 수 없다. M12의 "서버에 연결할 수 없을 때도 쓸 수 있어야" · "네트워크를 끊은 상태에서 끝까지" 테스트가 성립하려면 필요하다 | M12 |

## 3. 진행 방식 (M10~M14 공통)

**브랜치 · PR · 병합**
1. 마일스톤마다 최신 `origin/main`에서 새 브랜치를 만든다: `m10-touch`, `m11-mobile-screen`, `m12-solo-play`, `m13-pwa-twa`, `m14-store`. 새 브랜치 push가 막히면 세션 지정 브랜치 하나로 차례로 PR을 열고, 병합 뒤 `origin/main`으로 fast-forward해서 다음을 시작한다(`--force` 없이)

## M11 — 모바일 화면 · 성능 · 앱 생명주기

### 작업
1. **터치 레이아웃**: `client/src/ui/layout.ts`를 `configureLayout(화면 폭, 높이, 터치 여부)`로 바꾼다. **PC는 1920×1080 그대로.** 터치 모드는 논리 폭을 화면비에 맞춰 넓히고(1920~2400), 맵을 화면 높이 가득 그리고, 타이머 · 거점 게이지 · 팀 카드 · 미니맵을 좌우 칸 **위쪽**으로 옮긴다. 아래쪽 좌우는 엄지 영역으로 비운다. 2:1보다 좁은 화면(16:9)은 엄지 영역이 맵 아래 구석에 반투명으로 겹친다(그 구석에는 거점 · 탈출구가 없다). 화면 고정 · 전체 맵 보기(VISUAL_SPEC 1장)는 유지한다 — 줌이나 카메라 따라가기는 PC와 정보량이 달라져서 하지 않는다
2. **글자 크기**: 터치 모드에서 보조 글자 12 CSS px 이상, 주요 글자 14 CSS px 이상(높이 360 기준). 팀 카드는 아이콘 · 체력 칸 · 상태 한 단어로 줄인다. 배너 · 안내 · 점수판 · 괴물 경고도 같은 배율
3. **안전 영역(노치)**: viewport에 `viewport-fit=cover`를 넣고, 게임 영역 · 터치 컨트롤 · 로비 · 결과 · 토스트 · 깨우기 화면을 `env(safe-area-inset-*)`만큼 안쪽으로
4. **입력 방식별 문구**: 키 이름이 박힌 곳(행동 칸 라벨 "좌클릭/Shift/Q/우클릭/Space/E", `ROLE_CARDS.ability`, "E로 구조", "아무 키나 누르면 닫힘")을 입력 방식별로 나눈다. `storyText.ts`와 `STORY_TEXT.md`를 같이 고친다
5. **첫 실행 터치 튜토리얼**: 이 기기에서 처음 판에 들어가면(localStorage) 터치 모드 전용 안내를 화면 가운데에 띄운다. 스틱 · 버튼 자리를 CSS 도형으로 가리키고 역할별 문구를 보여 준다. 스틱을 움직여도 닫히지 않고 **안내를 탭해야 닫힌다.** 다시 보기는 점수판 화면에서. PC는 지금 안내 그대로
6. **성능 목표와 저사양 자동 전환**
   - 목표: 판 중 평균 **50fps 이상**(중급 휴대폰), 저사양 하한 **30fps**. 실기기 확인은 HUMAN_CHECKS
   - 첫 판은 기기 정보(CPU 코어 수 · 메모리)로 어림하고, 판 중 측정(예열 5초 제외)에서 평균이 **40fps 미만이 10초 넘게** 이어지면 **다음 판부터** 가벼운 모드(`scale 0.5` + 안개 갱신 주기 늘림)로 바꾸고 기기에 기억한다. 판 중에는 바꾸지 않는다(화면을 다시 만들면 끊기고, 다시 연결하면 괴물 정지 규칙이 걸린다). `?scale`을 직접 주면 그 값이 우선
   - 로비에 "그래픽: 자동 / 선명 / 가볍게"와 "진동: 켜기 / 끄기" 선택을 둔다(자동 판단을 되돌릴 수 있게)
7. **정적 파일 gzip 압축**(제안 14): `server/src/static.ts`에서 `Accept-Encoding`을 보고 텍스트 자산을 압축(결과는 메모리에 캐시)
8. **앱 생명주기 · 재접속** (`client/src/net.ts`, `app.ts`, 새 `client/src/lifecycle.ts`)
   - 수신 감시: 연결 중에 **4초** 동안 서버 메시지가 하나도 없으면(서버는 1초마다 pong) 끊고 바로 다시 연결
   - 재연결: 1 → 2 → 4초, 최대 5초 간격. 화면이 숨겨졌거나 오프라인이면 멈추고, 보이게 되거나(`visibilitychange`) 온라인이 되거나(`online`) `pageshow`가 오면 **즉시** 시도. 오프라인 동안 연결 시도 0회
   - 돌아오면 시계를 다시 맞춘다(빠른 ping 5번)
   - 숨겨져 있는 동안 소켓을 일부러 끊지 않는다. OS가 끊으면 서버 하트비트(10~20초)로 끊김이 잡히고 기존 30초 유예 규칙이 적용된다(DECISIONS)
   - **앱을 다시 열면 마지막 방으로**(제안 11): localStorage `decoy:lastRoom`(방 코드 + 시각), 30초 안이면 `?room=` 없이도 같은 자리로
   - "다른 탭에서 접속" 안내를 받은 기기에 "여기서 계속하기" 버튼
   - **뒤로 가기**(제안 10): 판 중에는 기록 항목을 하나 넣어 두고, 뒤로 가기에 "나가시겠어요?" 확인
9. **화면 꺼짐 방지(Wake Lock)**: 판이 시작되면 요청, 결과 · 로비에서 해제, 판 중 화면이 다시 보이면 재요청. 지원 안 함 · 거부는 조용히 넘긴다
10. **진동**: 내가 맞았을 때 한 번, 발각이 꺼짐 → 켜짐으로 바뀔 때 짧게 두 번. 2초 넘게 지난 일에는 울리지 않는다. 사용자가 아직 화면을 누르지 않았으면(`userActivation`) 부르지 않는다(콘솔 경고 방지). 설정에서 끌 수 있다
11. 오디오: 화면이 다시 보이면 AudioContext 재개 시도
12. **기기 저장 키 목록**(제안 12): 새 `client/src/storageKeys.ts`에 모든 키와 설명 · 보관 기간을 모으고, 그 밖에서 storage를 쓰면 실패하는 테스트와 처리방침 대조 테스트의 뼈대를 만든다. `storyText.ts` ↔ `STORY_TEXT.md` 동기화 테스트도 추가

### 자동 검증
- **단위**: `configureLayout`(PC는 항상 1920×1080, 터치는 화면비 규칙대로), 터치 글자 크기표 × 배율 ≥ 12px(높이 360), `actionSlots`, 저사양 판단 함수(예열 무시 · 임계 · 판 사이에만 · `?scale` 우선), 진동 판단 함수(활성화 전 · 오래된 일 · 발각 전환), 재연결 정책 함수(백오프 · 숨김/오프라인 정지 · 즉시 재시도), `lastRoom` 30초 만료, 저장 키 목록 밖 storage 사용 0건, 문구 동기화, gzip 응답(`content-encoding: gzip`, 크기 40% 이하, `x-decoy-server` 유지)
- **E2E `m11-screen`**
  - 휴대폰 높이 293 · 320 · 360에서 HUD 글자(디버그 훅 `getHudLayout()`으로 논리 크기 × 화면 배율)가 모두 12px 이상, 팀 카드 · 미니맵 · 타이머가 터치 컨트롤과 겹치지 않음
  - 안전 영역: CDP `Emulation.setSafeAreaInsetsOverride`(왼쪽 48 · 오른쪽 40 · 아래 21)를 걸면 터치 대상 · 캔버스 · 로비 버튼 · 토스트가 모두 안쪽에 있음
  - 로비 · 결과가 640×360 · 802×293에서 화면 안에 들어오고(또는 스크롤로 닿고) 가로 스크롤이 없음
  - **PC 회귀**: 1920×1080 m7 스크린샷 · 조준 E2E 그대로
- **E2E `m11-lifecycle`**
  - 숨김 → 이 탭의 소켓만 끊기(`page.routeWebSocket`) → 다시 보임: 3초 안에 같은 자리로 돌아오고 스냅샷이 다시 옴, 터치 상태는 초기화
  - 반쯤 열린 소켓(서버 → 클라이언트 중계만 멈춤): 수신 감시가 다시 연결
  - 오프라인 동안 연결 시도 0회(시도하면 콘솔 에러가 나서 그 자체로 실패), 온라인 이벤트 뒤 2초 안에 재연결
  - `?room=` 없이 다시 열어도 30초 안이면 같은 자리
  - 판 중 뒤로 가기 → 확인 창, "계속"이면 판 유지 · "나가기"면 로비
  - Wake Lock: 가짜 API로 호출 기록(시작 때 요청 · 복귀 때 재요청 · 결과에서 해제), 실제 API(헤드리스는 항상 거부)에서는 콘솔 0
  - 진동: 가짜 `navigator.vibrate`로 기록 — 내 피격 1번, 발각 전환 1번(발각이 이어지는 동안 추가 0번), 멈췄다 돌아온 뒤 지난 일 0번
  - 튜토리얼: 새 휴대폰 컨텍스트에서 터치 안내가 뜨고, 스틱을 움직여도 남아 있고, 탭하면 닫히고, 다시 열면 안 뜸. PC는 키보드 안내 그대로
  - 저사양: 디버그 훅으로 낮은 FPS를 넣고 판을 끝내면 다음 판이 `scale 0.5`, `?scale=1`을 주면 그대로. CPU 4배 느리게(CDP) 한 휴대폰 FPS는 **기록만** 한다(CI 러너 편차가 커서 게이트로 쓰지 않는다)
- 기존 전체 + 골든 해시 + CI 4작업 → 병합

### 사람이 확인할 것
- 실제 휴대폰(저사양 1대 포함)에서 FPS, 글자가 읽히는지, 노치 기기에서 가려지는 것이 없는지
- 화면이 꺼졌다 켜질 때 · 앱을 바꿨다 돌아올 때 자연스럽게 이어지는지(특히 괴물이 잠깐 나가면 판 전체가 멈춘다 — 판마다 합계 30초 넘으면 무효)
- 진동 세기 · 패턴, Wake Lock이 실제로 화면을 켜 두는지, 첫 탭에서 소리가 나는지

- `PLAY_STORE_GUIDE.md`: 요청한 단계 제목이 모두 있고, 적힌 환경변수 이름 · 경로가 서버 코드와 글자 그대로 같음
- 전체 회귀(단위 · 봇 · E2E · 지연 · 배포) + 콘솔 0 → CI 4작업 → 병합 → 최종 보고
