# DECOY 비주얼 리마스터 · 모바일(안드로이드) 계획 — M10~M15

먼저 그래픽을 새로 만들고(M10), 그 그래픽을 기준으로 휴대폰 브라우저와 안드로이드 앱(PWA → PWABuilder TWA)에서도 할 수 있게 만든다(M11~M15). PC와 휴대폰은 같은 방에서 함께 한다. 목표는 **구글 플레이에 비공개 테스트로 올릴 수 있는 상태**까지이고, 계정 · 결제 · 서명 키가 필요한 일은 `docs/PLAY_STORE_GUIDE.md`로 넘긴다.

| 마일스톤 | 내용 | PR |
|---|---|---|
| **M10** | 비주얼 리마스터: 선명도(DPR) · 그래픽 품질 단계 · 안개 방식 변경 · 새 그래픽 · UI | 3개 (10a · 10b · 10c) |
| **M11** | 터치 조작 (요청의 옛 M10) | 1개 |
| **M12** | 모바일 화면 · 성능 · 앱 생명주기 (옛 M11, 새 그래픽 기준) | 1개 |
| **M13** | 혼자서도: 봇과 연습 · 빠른 매칭 · 앱 셸 캐시 (옛 M12) | 4개 (13a~13d) |
| **M14** | PWA · TWA 준비 (옛 M13) | 1개 |

**바꾸지 않는 것**

- 게임 규칙 · 판정 · 정보 차단. 서버는 PC인지 휴대폰인지 모르고, 입력은 지금의 `InputFrame {seq, mx, my, aim, held, pressed}` 그대로다
- 역할 색(러너 `#3B82F6` · 가드 `#A855F7` · 스카우트 `#22C55E` · 괴물 `#EF4444`), 괴물 화면의 생존자 흰색 위장(`#F8FAFC`), 색만으로 구분하지 않기(형태도 다르게), 게임 정보가 효과에 묻히지 않기
- PC 조작(키보드 · 마우스). 터치 화면 요소는 터치 기기에서만 만든다
- 수치는 `config/balance.json`, 문구는 `client/src/data/storyText.ts` + `docs/STORY_TEXT.md`, 메시지 타입은 `shared/src/types.ts` 한 곳
- 콘솔 에러 · 경고 0, 규칙마다 단위 테스트, 마일스톤마다 자동 검증 통과 후 병합

## 0. 지금 구조에서 걸리는 것

코드를 영역별로 읽고, 헤드리스 Chromium으로 실험해 확인한 사실이다.

### 0.1 그래픽 (M10)

| 영역 | 지금 | 확인한 것 |
|---|---|---|
| **흐릿함** | 게임 크기(백버퍼)를 1920×1080으로 고정하고 Phaser `Scale.FIT`로 CSS 확대 · 축소한다. Phaser 3.90은 devicePixelRatio를 보지 않는다 | 흔한 PC 설정 5가지(맥북 @2, QHD, FHD @125%, 윈도 노트북 125% 창, 1080p 창) 모두 1:1이 아니었다(×1.5 ~ ×0.85 리샘플). 원인 6가지: ① 백버퍼 고정 ② Phaser 글자 해상도가 항상 1 ③ 바닥 합성 캔버스를 0.93배로 한 번, 화면 배율로 또 한 번 리샘플 ④ 빛 지도 저해상도 ⑤ 미니맵 캔버스 ⑥ 캔버스가 반 픽셀 어긋나 합성기가 전체를 다시 샘플. 시제품으로 다 고치면 글자 선명도 지표가 0.54~0.84 → 0.99~1.00, 감옥 철창 0.51 → 0.88 |
| **?scale** | `?scale=`(빈 값) · `?scale=0` · `?scale=%20`이면 **0.25배**(백버퍼 480×270)가 된다. 한 번 붙인 `&scale=0.5`는 새로고침 · 재연결에도 주소에 남는다 | 주소에 붙이지 않았다면 배포판 PC가 흐린 원인은 ?scale이 아니라 위 6가지다. 테스터 안내 문서 3곳이 `&scale=0.5`를 권한다 |
| **안개** | 바닥 · 벽 · 거점 · 탈출구를 Canvas2D 한 장에 그리고 빛 지도(검정 바탕)를 곱한다 → 시야 밖은 완전한 검정 | 캐릭터는 원래 안개 위에 그리고, 시야 밖 상대가 안 보이는 것은 **서버가 보내지 않아서**다. 그래서 바탕을 검정 대신 어두운 회청색으로 바꾸기만 해도 구조가 보이고 정보 차단은 그대로다(시제품: 시야 밖 바닥 13 · 벽 23 · 시야 안 47, 비용 변화 없음). 맵 구조와 거점 · 탈출구 상태는 이미 양쪽에 공개된 정보라 새는 것이 없다 |
| **형태 · 색** | 생존자 셋이 같은 "원 + 노치"이고 색만 다르다 | 제2색맹 시뮬레이션에서 러너 · 가드 색 차이 ΔE 2.8(사실상 같은 색), 노랑 · 빨강 부채꼴도 비슷한 올리브색. 경고 배너(흰 글자 / `#F59E0B`) 대비 2.15:1, 기둥 대비 1.55:1. 거점 배지가 그 위에 선 캐릭터를 덮는다. Tab 점수판과 조작 안내가 겹친다 |
| **Phaser 효과** | 쓰지 않음 | 내장 FX 14종(Bloom · Vignette · Glow · ColorMatrix 등)은 **WebGL 전용**이고 Canvas에서는 조용히 무시된다. Bloom은 해상도를 낮출 수 없는 11패스라 비싸다(헤드리스 0.15~0.33배). 카메라에 FX를 걸면 HUD 글자도 번진다 → 월드 레이어에만 건다. 파티클은 두 렌더러 모두 된다 |
| **에셋 · 폰트** | 외부 에셋 없음. CSS가 'Noto Sans KR'을 이름만 지정하고 실제로는 OS 글꼴 | 이 작업 환경에서 kenney.nl · opengameart · itch.io 등 **CC0 에셋 사이트가 모두 차단**된다. npm의 Kenney 재업로드는 출처가 불분명하다 → 그래픽은 전부 코드(Canvas2D · Path2D · 셰이더)로 만든다. 한글 웹폰트는 CC0가 사실상 없다. Noto Sans KR(SIL OFL 1.1, 예약 이름 없음)을 UI 글자 + 상용 한글 2,350자로 줄이면 woff2 한 개 약 300KB |
| **로고** | `docs/images/logo_decoy.png` **213×213** | DPR 2에서 로비 큰 로고(200 CSS px)가 1.9배로 늘어나 흐리다. 앱 아이콘(512)도 확대본이 된다 |
| **테스트** | E2E는 픽셀을 읽지 않고 디버그 훅(`getDrawn` 등)으로 판정. 여러 탭 E2E는 Canvas 렌더러, WebGL은 스모크 1개(SwiftShader) | CI에는 GPU가 없어 WebGL 4탭은 1~3fps다. 높은 품질은 WebGL 1탭 스크린샷 · 픽셀 검사로 확인하고 성능 게이트는 Canvas로 둔다 |

### 0.2 모바일 (M11~M15)

| 영역 | 지금 | 모바일에서 생기는 일 |
|---|---|---|
| 입력 | 괴물 `aim`은 커서 위치가 아니라 **목표 절대 각도**. 서버는 구조(`RESCUE`)만 `held`, 나머지는 `pressed`로 처리 | 조이스틱 각도를 `aim`에 그대로 넣으면 된다(540°/초 회전 상한도 그대로). 그런데 지금은 **캔버스를 터치하면 괴물 공격**이 나가고(pointerType을 안 봄), **조준이 마지막 손가락을 따라간다**(Phaser activePointer) |
| 공격 방향 | 서버는 공격을 회전보다 먼저 처리하고, 방향은 그 순간의 `face` | "놓으면 공격"을 그대로 하면 스틱을 휘두르고 바로 놓을 때 예전 방향으로 나간다 → 클라이언트가 발사를 잠깐 늦춘다(M11) |
| 이동 크기 | 서버는 길이 1 초과만 줄인다. PC는 8방향 · 길이 1 | 조이스틱을 반만 밀면 느리게 걷는다 → 데드존 밖에서 길이 1로 보낸다 |
| 화면 | 논리 1920×1080, HUD는 캔버스 안, 로비 · 결과는 HTML | 844×390 휴대폰에서 글자 5~11 CSS px, 결과 화면 **위쪽이 잘리고 스크롤도 안 된다** |
| 연결 | 로비 홈은 **서버에 연결된 뒤에만** 그린다. 재연결은 1초 고정 무한 반복 | 서버가 잠들었거나 오프라인이면 누를 버튼이 없다 |
| 서비스 워커 | `wake.html`만 캐시. "게임 코드는 캐시하지 않는다" | **오프라인에서 앱을 열 수 없다** |
| 시뮬레이션 | `server/src`에 있고 Node 의존은 **`node:crypto` 두 곳뿐** | 기기 안에서 그대로 돌릴 수 있다(서버 코드 약 24KB 증가) |
| 봇 | `?bots=1`은 개발용: **괴물 봇은 공격하지 않음**, 생존자는 순찰만. 봇 이름 `봇 runner`처럼 역할이 드러남 | 빠른 매칭 · 연습에는 실전 봇이 필요하다 |
| 길찾기 | 경로를 못 찾으면 **매 틱 A\*를 다시 돈다**(봇 판 틱 시간의 약 97%) | 휴대폰 메인 스레드와 Render 무료 CPU(0.1개)에 부담 |
| 서버 경로 | 없는 경로는 모두 `index.html` 200. `.webmanifest` MIME 없음. 압축 없음(번들 1.28MB, gzip 약 350KB) | `/privacy` · `/.well-known/assetlinks.json`은 명시 라우트가 필요하다 |
| 기기 저장 | sessionStorage `decoy:seat:<방>`, localStorage `decoy:seats` · `decoy:name`, `decoy-wake-reloads`, Cache `decoy-wake-v1`. 쿠키 · 분석 · 외부 요청 없음 | 개인정보처리방침의 근거. 작업하며 키가 늘어난다 |
| 서버 로그 | 판 시작 때 `방 CODE 판 시작 (닉네임:역할, …)` | Render 로그에 닉네임이 남는다 |
| 저장소 · CI | **private**(문서에는 "공개"), 브랜치 보호 없음, CI 4작업 한 번 약 10분 과금(M10b에서 push마다 빠른 검사 + PR 병합 직전 전체 검사로 나눔 — 3절). `main` 병합 → Render 자동 배포 | 병합 전에 4작업 성공을 직접 확인해야 한다. **병합할 때마다 서버가 다시 떠서 진행 중인 방이 사라진다** |

## 3. 진행 방식 (공통)

**브랜치 · PR · 병합**
1. 로컬 `main`은 쓰지 않는다(오래된 기록). 항상 `git fetch` 뒤 `origin/main`에서 시작한다
2. 커밋 메시지는 한글 한 줄. push는 작업 단위를 마쳤을 때만 한다(CI 시간 절약)
3. push마다 도는 빠른 검사(CI `ci.yml`의 `quick`: 타입 · 린트 · 포맷 · 단위 · 핵심 E2E `@core`)가 success여야 한다. **PR마다 병합 직전**에 그 PR 브랜치에서 `ci.yml`을 수동 실행(workflow_dispatch)해 전체 검사(빠른 검사 + 전체 E2E 4샤드 + 지연 봇 판 + 배포 검증)를 돌리고, 마지막 작업 **`전체 검사 결과`가 PR의 지금 head 커밋에서 success일 때만** 머지 커밋(`… 병합 (#N)`)으로 병합한다(병합 API에 그 head SHA를 같이 넘긴다). 그 뒤에 push가 있으면 다시 돌린다. 세션에서 직접 돌린 E2E 결과도 PR 설명에 남긴다 (M10b에서 바꿈 — DECISIONS 4절 "CI 나누기")
4. 병합 뒤 `main`의 CI가 success가 될 때까지 확인한다(그래야 Render가 배포한다). 실패하면 다음 작업보다 고치는 PR이 먼저다. 병합 시각 · `main` CI 결과를 `PROGRESS.md`에 남긴다. **병합할 때마다 진행 중인 방이 사라진다**(이번 작업으로 약 12번)
5. `render.yaml`의 `plan: free`는 바꾸지 않는다(단위 테스트가 확인한다)

**병렬 작업**: 마일스톤(PR) 안에서만 나눈다. 각 PR의 "작업 단위" 표처럼 **파일 소유를 고정**하고, **표에 없는 파일은 메인만 고친다.** 공통 계약(인터페이스 · 메시지 타입)은 먼저 한 커밋으로 고정한다. 작업자는 각자 worktree에서 단위 테스트까지, 통합 · E2E · 문서는 메인이 한다(E2E는 고정 포트를 써서 동시에 돌리지 않는다).

**PR마다 할 일**: 이 문서 체크박스 · `PROGRESS.md`(3~5줄 + E2E 소요 시간) · `DECISIONS.md` · `HUMAN_CHECKS.md` 갱신, 수치를 바꿨으면 `GAME_DESIGN.md` 변경 이력. 같은 문제로 세 번 넘게 막히면 `PROGRESS.md`에 `> 보류:`로 남기고 넘어간다.

**콘솔 규칙의 예외**: 서버를 일부러 끄는 테스트에 한해, 그 테스트에서만 브라우저가 스스로 찍는 연결 실패 로그(`WebSocket connection … failed`, `Failed to load resource`)를 허용한다. `watchConsole`에 테스트별 허용 목록 인자를 더하고, 허용한 메시지 수가 재시도 정책 이하인지도 확인한다. 앱은 오프라인일 때와 연습 모드에서는 연결을 아예 시도하지 않는다.

**CI 시간**: push마다 도는 CI는 빠른 검사 작업 하나(3분 안팎)다. 전체 E2E는 러너(GPU 없음, SwiftShader)에서 한 작업으로 25~31분이 들어 30분 제한에 걸렸으므로, 러너에서 잰 파일별 시간(`tests/e2e/durations.json`)으로 고르게 나눈 4개 작업이 동시에 돈다(`scripts/e2e-shard.mjs`, 작업마다 제한 45분, 러너가 달라 고정 포트가 충돌하지 않는다). 새 E2E 파일은 기본 무게로 자동으로 어느 샤드엔가 들어가고, 러너 시간이 크게 바뀌면 시간표를 고친다. 남은 Actions 분(무료 월 2,000분)을 PR마다 확인하고, **마일스톤마다 쓴 Actions 분을 `PROGRESS.md`에 적는다**.

**CI 기다리기**: 알림에만 기대지 않는다. 실행을 건 뒤 직접 주기적으로 상태를 확인하고, 세션이 멈춰도 돌아오도록 확인 예약(`send_later`)을 걸어 둔다. **취소 · 시간 초과도 결과**다: 원인을 보고 바로 고치거나(시간 초과면 샤드 · 제한 조정) 한 번 다시 돌린다. 알림이 오지 않아 8시간 멈춘 적이 있다(2026.10.08).

## M10 — 비주얼 리마스터

목표: PC에서 선명하고, 어두운 시설 · 청록 네온 · 붉은 괴물 분위기의 새 그래픽. 맵 구조는 항상 어둡게 보이고, 품질 높음 · 중간 · 낮음이 있다. 규칙 · 판정 · 정보 차단 · 역할 색 · 흰색 위장 · 형태 구분 · 정보 우선은 그대로다.

### 새 그래픽의 원칙 (VISUAL_SPEC 새 판의 뼈대)

- **형태 문법**: 시설 = 직각 모듈 판 + 가는 청록 네온(직선), 생존자 = 둥근 형태, 괴물 = 뾰족한 형태(톱니 망토 · 발톱), 거점 = 원형 패드 + 마름모 문양, 탈출구 = 사각 방폭문 + 바닥 화살표, 감옥 = 격자 철창 + 자물쇠
- **역할 실루엣**(생존자 팀 화면 · 로비 · HUD · 결과): 러너 = 앞이 뾰족한 물방울 + 등의 » 무늬, 가드 = 몸 원 + 앞쪽 초승달 방패, 스카우트 = 원 + 렌즈 고리 + 앞쪽 사각 렌즈. 같은 몸 원(판정 반지름)을 공유하고 앞 돌출은 지금 노치 범위 안. 흑백 · 12px에서도 외곽선만으로 구분되는 것을 시제품으로 확인했다
- **괴물 화면의 생존자**: 하나의 공통 실루엣(원 + 노치, `#F8FAFC`) · 같은 크기 · 같은 걸음 · 부상 표시 없음. 그리기 함수가 역할 · 체력 인자를 아예 받지 않게 해서 코드로 막는다. 능력 노출 1초에는 역할색 테두리 + 머리 위 역할 문양(이때도 색만으로 구분하지 않게)
- **괴물**: 위에서 본 망토(둥근 후드, 뒤 자락 5갈래 톱니, 어두운 얼굴에 흰 분홍 발광 눈, 앞 발톱 2개). 촉수 없음(판정이 커 보이지 않게)
- **재질**: 바닥 = 강판 패널 + 이음선 + 고정 시드 노이즈 + 드문 데칼, 벽 = 칸 안에서 2.5D(윗면 + 앞면 + 하이라이트 + 바닥 그림자), 기둥 = 깎은 8각 + 밝은 윗테두리(어둠 속에서도 2.5:1 이상). **입체 표현은 벽 · 기둥 칸 밖으로 나가지 않는다**(그림 경계 = 판정 경계)
- **조명과 안개**: 바닥을 밝히는 빛은 시야뿐이다. 생존자 시야 = 손전등 웅덩이(판정 반경 안쪽 1.2타일에서 흐려짐, 경계에 그 사람의 역할색 림), 괴물 부채꼴 = 판정과 같은 딱 잘린 경계 + 가장자리 선. **시야 밖 = 어두운 구조**(밝기 하한, 채도 낮춤, 이음선 · 데칼 없음), 시야 안은 2.5배 이상 밝게. 시설 발광(벽 네온, 거점 링, 탈출구 등, 감옥 철창)은 어둠 속에서 30%, 빛 속에서 100%. 상대 팀 광원으로 환경을 비추지 않는다
- **팔레트**: 바닥 · 벽 · 네온 · 경고 색을 새로 정하되, 역할 4색과 `#F8FAFC`는 캐릭터 · 역할 UI 전용, 빨강은 괴물 · 부채꼴 · 감옥 · 피해 전용, 주황은 경고 전용, 청록은 시설 · 목표. 괴물 화면에서 "흰 원 = 생존자"이므로 맵에 흰색 · 밝은 둥근 장식을 두지 않는다. 글자에는 역할색의 밝은 변형(패널 위 6.3~6.9:1)을 쓴다
- **부채꼴**: 색(`#EAB308` / `#EF4444`)과 보간 시간(0.1 / 0.4초)은 규칙대로. 채움을 0.30 / 0.45에서 0.20 / 0.28로 낮추고 가장자리 선을 더하며, 빨강 상태에는 사선 해치 + 펄스(색약 대비). 괴물 몸이 자기 빨강 부채꼴 위에서 2.34:1로 묻히던 문제를 외곽선으로 푼다
- **정보 우선 규칙**(VISUAL_SPEC 새 장): 레이어 순서 고정(구조 → 바닥 문양 → 시야 빛 → 장식 입자 → 범위 표시 → 캐릭터 → 캐릭터 부착 표시 → 안개 위 정보 마커 → 배너 · HUD), 블룸 · 비네트 · 색보정은 구조 · 발광 레이어에만(캐릭터 · 범위 · 마커 · 글자 · HUD에는 걸지 않음), 캐릭터 몸과 바깥 링 대비 3:1 이상(효과를 켜도 끈 상태의 80% 이상), 장식 입자 알파 0.2 이하 · 몸 위에 그리지 않음, 이벤트 효과 0.4초 이하, 범위 표시는 실제 판정값(공격 1.2타일 90°, 밀치기 2, 포효 10, 구조 1.2, 캠핑 4, 거점 2.5, 탈출구 1.5), 배지 · 라벨이 캐릭터를 덮지 않음, 글자 대비 4.5:1(큰 글자 3:1), 어둠 속에서 움직이는 것은 정보 마커뿐, **품질은 장식만 바꾼다**
- **상대 쪽 잔여 효과**: 상대에게서 나오는 효과(잔상 · 파티클 · 불꽃)는 지금 그린 엔티티를 따라가거나 받은 이벤트 좌표에서만 생기고, 출처가 사라지면 즉시 없앤다(지금 돌진 잔상은 괴물이 시야를 벗어난 뒤에도 0.25초 남는다 → 고친다)
- **애니메이션**: 생존자(숨쉬기, 이동 거리 기반 걷기, 피격, 보호 거품, 수감 흩어짐 → 감옥에서 나타남, 구조, 탈출, 사망, 질주 · 밀치기 · 탐지), 괴물(자락 물결, 걷기, 공격 준비 — 발톱 들기 + 범위가 준비 시간에 맞춰 차오름, 타격 호, 돌진 늘어남 + 잔상, 기절, 포효 충격파), 오브젝트(거점 눈금 점등 · 스캔선 · 정지 · 완료, 탈출구 활성 맥동 · 개방 진행 · 미닫이, 감옥 자물쇠 회전 · 문 열림). **규칙 시간(준비 0.4초, 돌진 0.25초, 기절 1.5초, 보호 4초, 구조 3초, 개방 3초 등)은 `balance.json`에서 읽는다.** 장식 연출 시간만 그래픽 상수
- **UI**: 모서리를 깎은 어두운 유리 패널 + 얇은 청록 테두리(concept_06의 게이지 언어), 같은 깎은 모서리 버튼, 24 격자 선 아이콘(코드 SVG 경로 하나를 HTML 인라인 SVG와 Phaser 텍스처가 같이 씀), 숫자는 고정폭. 로비 배경은 실제 맵을 청록 선으로 그린 설계도. 로고는 그대로 쓰고 "DECOY" 글자는 코드로 얹는다
- **컨셉 이미지에서 가져오지 않는 것**: 거점별 색(역할색과 겹침), 부채꼴 3단계, 괴물 여러 마리, 아이템 상자. 스토어 이미지에도 컨셉 이미지는 쓰지 않는다

| 항목 | 높음 | 중간 | 낮음 |
|---|---|---|---|

| 발광 | 미리 구운 발광 스프라이트 (+ Bloom은 실측해서 감당될 때만) | 미리 구운 발광 | 정적 발광만 |
| 비네트 · 색보정 | 월드 레이어 postFX | 구운 오버레이 1장 · 색보정 | 없음 |
| 파티클 동시 상한 | 400 | 150 | 40 |
| 프레임 애니메이션 | 전부 | 전부 | 프레임 절반 |
| **정보 요소(캐릭터 · 범위 · 마커 · 배지 · HUD)** | **같음** | **같음** | **같음** |

- Canvas 렌더러이면 어느 단계든 WebGL 전용 기능이 0개가 되게 자동으로 낮춘다(Canvas에서 Shader 객체를 만들면 예외가 나는 것을 확인했다)
- **자동 선택**: `?quality=high|medium|low` > 로비에서 고른 값(localStorage `decoy:quality`) > 자동. 자동은 Canvas 렌더러이거나 소프트웨어 WebGL이면 낮음, 터치 기기는 중간(코어 4개 이하 또는 메모리 3GB 이하면 낮음), 하드웨어 WebGL PC는 높음. **PC는 코어 수 · 메모리로 내리지 않는다**(사무용 노트북 다수가 4코어/8GB라 잘못 켜질 위험)
- **실행 중 자동 하향**: 판 중 예열 5초 뒤 평균 40fps 미만이 10초 넘게 이어지면 한 단계 내린다(판 중 한 번, 재연결 · 장면 재시작 없이). 올리기는 사용자가 고를 때만. 모바일 기준값은 M12에서 다시 잰다
- `?scale`은 "해상도 배율"로 재정의한다(값이 비었거나 0 · 음수 · 숫자가 아니면 **무시**, 있으면 0.25~1을 위 해상도에 곱함). 옛 `&scale=0.5` 링크도 "가볍게"로 계속 동작한다. 테스터 안내 문서의 `&scale=0.5`는 "그래픽 품질: 낮음"으로 바꾼다

### M10a — 선명도 · 품질 단계 · 안개 방식 (기반)

2. **판정 불변 골든 테스트**(제안 15)
3. **해상도**: 새 `client/src/render/resolution.ts`(순수 함수) — 표시 CSS 크기 × min(DPR, 단계 상한, 픽셀 상한)으로 백버퍼를 정하고 카메라 zoom으로 논리 1920×1080을 유지한다. `Scale.FIT` → `Scale.NONE` + 캔버스를 기기 픽셀 격자에 맞춰 직접 배치 + `game.scale.refresh()`(빠뜨리면 조준이 18° 틀어지는 것을 시제품에서 확인). 창 크기 · DPR 변경(모니터 이동 · 브라우저 확대)을 듣고 디바운스해 다시 맞춘다. 나중에 터치 레이아웃(논리 폭 1920~2400)도 같은 함수를 쓴다
4. **글자**: 새 `client/src/ui/text.ts` — 모든 Phaser 글자를 여기서만 만든다(해상도 = zoom, 텍스처 정수 텍셀, 위치를 기기 픽셀에 맞춤). 거점 A · B 배지 글자는 0.93배 컨테이너 밖으로
5. **바닥 · 미니맵 해상도**: 정적 맵을 목표 배율로 직접 그려 이중 리샘플을 없애고, 합성 캔버스 · 미니맵을 zoom에 맞춘다(단계 상한 적용)
6. **안개 방식 변경**: 빛 지도 바탕을 검정에서 밝기 하한(어두운 청회색, 값은 그래픽 상수 + VISUAL_SPEC)으로. WebGL은 "정적 맵 텍스처 한 번 업로드 + 작은 빛 텍스처만 갱신해 곱하기"(GPU 합성), Canvas는 지금처럼 한 장 합성. 두 구조를 시제품으로 비교해 DECISIONS에 남긴다. 괴물 부채꼴처럼 딱 잘려야 하는 경계는 빛 지도에 기대지 않고 벡터 선으로 덧그린다. 미니맵도 같은 방식. 상대 잔여 효과 규칙(돌진 잔상 즉시 제거) 적용
7. **품질 단계**: 새 `client/src/gfx/quality.ts`(자동 선택 · 우선순위 · 판 중 하향, 순수 함수) · `presets.ts`(위 표). 레이어를 월드(효과 대상) · 엔티티(효과 없음) · HUD(효과 없음)로 나눈다(카메라 FX는 HUD까지 번지는 것을 확인함). 로비에 "그래픽: 자동 / 높음 / 중간 / 낮음"
8. `?scale` 빈 값 버그 수정과 재정의, 문서 안내 수정
9. **문서**: GAME_DESIGN 3.1 안개 문장("맵은 기본적으로 검게 가려져 있다" → "맵 구조는 항상 어둡게 보이고, 캐릭터와 움직이는 것은 지금 보는 곳에서만") + 변경 이력, TECH_SPEC 4~5장, CLAUDE.md 그래픽 · artifacts 규칙(2절), DECISIONS(D7 브랜치 포함), `PLAY_STORE_GUIDE.md` 1부(제안 19), "공개 저장소" 문구 정정(제안 22), `BUILD_PLAN.md`에 이 문서 연결, `.gitignore`에 `!artifacts/remaster/`

5. **조작 규칙** (DECISIONS에 적는다)
   - 이동: 데드존 15%, 그 밖은 **길이 1**(PC와 같은 최고 속도), 방향은 360°
   - **조준 스틱 상태**: ① 대기 ② 조준 중(데드존 밖에 한 번이라도 나감) ③ 발사 대기. 데드존 안에서는 `aim`을 갱신하지 않고 마지막 바깥 각도를 유지한다. ②에서 데드존 밖에서 떼면 ③으로 가고 그 순간 각도 θ를 고정해 `ATTACK`을 보낼 때까지 `aim = θ`를 보낸다. 예측 `face`가 θ ±10° 안이면 그 프레임에, 아니면 최대 0.35초 뒤에 `ATTACK`. ②에서 데드존으로 돌아와 떼면 **취소**. ①에서 0.25초 안에 떼면(짧은 탭) 지금 방향으로 공격, 더 길면 아무것도 안 함. 쿨타임 중이거나 행동 불가(시작 대기 · 기절 · 돌진 · 준비 중)이면 ③에 들어가지 않는다
   - 조준 스틱을 놓고 있을 때는 이동 방향을 본다(멈춰 있으면 마지막 방향). 단 ③ 동안과 `ATTACK`을 보낸 프레임까지는 θ
   - **돌진 버튼**: 누르면 그 자리에서 작은 스틱이 되어 끈 방향을 `aim`으로 보내다가 떼면 같은 발사 대기를 거쳐 `DASH`. 데드존 안에서 떼면 지금 방향으로 즉시. 다른 손가락으로 조준 스틱을 잡고 있으면 그 각도로 `DASH`
   - 포효 · 시야 모드 · 능력: 탭 = `pressed`. 구조: 누르는 동안 `held RESCUE`
   - 손가락이 사라지는 모든 경우(`pointercancel` · `lostpointercapture` · blur · 숨김 · 화면 회전)에 터치 상태를 초기화한다
6. **가로 화면**: "가로로 돌려주세요"는 JS 없이도 뜨게 정적 마크업 + CSS `@media (orientation: portrait) and (pointer: coarse)`(태블릿 포함). 세로 동안 입력을 보내지 않는다. **전체 화면 + 방향 고정은 사용자 탭 핸들러 안에서만** 부른다(로비의 준비 · 코드 입장, 판 안 터치 레이어의 첫 탭, "전체 화면" 버튼). 판 시작은 서버 메시지라 그때 자동으로 부르면 거부된다. "전체 화면" 버튼은 터치 모드이고 브라우저 안일 때만 로비 · 세로 안내 · 터치 HUD에 둔다. 실패는 조용히 넘긴다
7. **브라우저 기본 동작 막기**: viewport `maximum-scale=1, user-scalable=no`, `html, body`에 `overscroll-behavior: none`, 게임 영역 · 터치 레이어에 `touch-action: none` · `user-select: none` · `-webkit-touch-callout: none` · `-webkit-tap-highlight-color: transparent`, 판 중 문서 전체 contextmenu 차단. 로비 · 결과는 `touch-action: pan-y`(스크롤), 입력칸은 선택 허용
8. **로비 · 결과 휴대폰 맞춤**(제안 3): `(pointer: coarse)`에서 버튼 · 입력칸 48px, `(max-height: 500px)`에서 로고를 작게 옆으로, 방 화면 준비 · 시작 줄 고정, 결과 상자 위쪽 잘림 수정, 결과 표 가로 스크롤
9. **오디오**: 마우스는 pointerdown, 터치 · 펜은 pointerup에서 AudioContext를 만들거나 재개한다(터치 pointerdown은 사용자 활성화가 아니라 경고가 난다)
10. **문서**: GAME_DESIGN 2장 조작표 "터치" 열 + 변경 이력, STORY_TEXT 버튼 이름, DECISIONS, HUMAN_CHECKS

### 자동 검증
- **단위**
  - 터치 상태 기계: 손가락별 독립, 데드존 · 길이 1, 조준 스틱 상태 규칙 전부(예측 `face`가 이미 θ ±10° 안이면 다음 프레임에, 아니면 수렴 프레임 또는 0.35초에 `ATTACK` 정확히 1번 / 가운데로 돌아와 떼면 0번 / 짧은 탭 1번 · 긴 데드존 누름 0번 / ③ 동안 이동 입력이 있어도 `aim = θ` / 쿨타임 · 행동 불가면 ③ 없음), 돌진 끌기(이동과 90° 다른 쪽으로 돌진), 취소 이벤트마다 이동 · `RESCUE` 0, 가장자리 띠 터치 무시
  - **입력 형식 동일성**: W ↔ 스틱 위, W+D ↔ 45°, E 누르기 ↔ 구조 버튼, Space ↔ 능력, Shift · Q · 우클릭 ↔ 돌진 · 포효 · 시야, 좌클릭 ↔ 조준 스틱 놓기, 커서 쪽 Shift ↔ 돌진 끌기. 두 프레임의 키 집합이 같고, JSON 왕복 + 서버 `sanitizeInput` 뒤 값이 같고, 같은 시퀀스를 `Game`에 넣은 결과(위치 · 공격 준비 · 돌진 방향)가 같다. 생존자 `aim`은 둘 다 NaN
  - `InputSampler` 회귀: 키 자동 반복은 `pressed`를 다시 켜지 않음, 터치 pointerdown은 `ATTACK` 없음, 마우스 좌클릭은 그대로 `ATTACK`, 터치 pointerdown에서는 AudioContext를 만들지 않음
  - 골든 해시 불변
- **E2E `m11-touch`** (휴대폰 가로 에뮬레이션, 기능 시험은 기기 배율 1로 덮어써 속도 확보)
  - 감지: 휴대폰 컨텍스트에 터치 레이어, PC 컨텍스트에는 0개, `?touch=1|0` 강제. 기존 마우스 E2E(m2 · m4) 그대로
  - **멀티터치**: 괴물이 왼쪽 스틱 위 + 오른쪽 스틱 θ를 동시에 → 입력 로그 `my≈-1` · `aim≈θ`, 서버 정답에서 괴물이 위로 움직이고 `face`가 θ로 수렴. 오른쪽만 떼면 `ATTACK` 1번 + 서버 공격 준비, 이동은 계속
  - 오입력 회귀: 왼쪽 스틱만 2초 끌어도 `ATTACK` · `MODE` 0, 조준이 왼손을 따라가지 않음
  - 크기 · 위치: 휴대폰 4종(높이 293~360 포함) · 태블릿 가로에서 모든 터치 대상 48×48 이상, 안 겹침, 화면 안, 가장자리 띠 밖. 생존자는 조준 스틱 0개
  - 기본 동작: meta viewport와 계산된 CSS 값, 스틱을 끌어도 `pointercancel` 0회, 길게 눌러도 선택 문자열 빔, contextmenu 막힘. 핀치는 CDP `synthesizePinchGesture`로 **보호하지 않은 대조 페이지가 실제로 확대되는 것을 먼저 확인한 뒤** 게임 페이지가 `visualViewport.scale` 1인지 본다. 대조 페이지도 확대되지 않으면(헤드리스 한계) 이 항목은 HUMAN_CHECKS로만 둔다
  - 세로 안내: 휴대폰 · 태블릿 세로에서 보이고 입력 없음, 가로로 바꾸면 사라짐, JS를 끈 세로 컨텍스트에서도 보임, PC 좁은 창에서는 안 뜸
  - 전체 화면: 가짜 API로 기록 — 서버 `match` 수신 시점 호출 0회, 첫 탭에서 1회
  - 레이어: 휴대폰 결과 화면의 모든 버튼(왼쪽 40% 안 포함)을 탭해 동작, 왼쪽 영역에서 결과 스크롤
- **E2E `m11-mixed` — PC와 휴대폰이 같은 방에서 한 판 끝까지**
  - 괴물 PC · 러너 휴대폰 · 가드 PC · 스카우트 휴대폰. 휴대폰 로비에서 역할 선택 · 준비를 탭으로
  - 거점은 테스트 훅으로 0.99 → **휴대폰 러너(왼쪽 스틱)와 PC 가드(W)가 북문 반경 안에 3초 머물러 문이 열림** → 둘 다 걸어 들어가 탈출 → 휴대폰 스카우트는 최후의 30초 안에 사망 처리 → 4명 모두 "생존자 승리" · 등급 확인 → 휴대폰에서 다시 하기. 터치 입력이 실제로 문 개방 · 탈출에 들어갔는지 서버 정답으로 확인
  - 변형: 휴대폰 괴물이 오른쪽 스틱으로 PC 러너를 조준하고 놓아서 맞힌다(서버 정답 체력 2 → 1)
  - 4개 컨텍스트가 보낸 WebSocket `input` 원문의 키 · 값 형식이 같다, 모든 컨텍스트 콘솔 0
- 기존 전체 + 빠른 검사 CI + 병합 직전 전체 검사 → 병합

## M12 — 모바일 화면 · 성능 · 앱 생명주기 (새 그래픽 기준)

### 작업
1. **터치 레이아웃**: `layout.ts`를 `layout()` 객체(getter)로 바꾸고 `configureLayout(화면 폭, 높이, 터치 여부)`. **PC는 1920×1080 그대로.** 터치 모드는 M10 HUD 부품을 다시 배치한다: 2:1 이상 화면은 논리 폭을 넓히고(1920~2400) 맵을 화면 높이 가득, 타이머 · 게이지 · 팀 카드 · 미니맵을 좌우 칸 **위쪽**으로, 아래쪽 좌우는 엄지 영역. 2:1보다 좁은 화면(16:9)은 위 · 아래 띠를 남기고 맵을 줄인 배치를 따로 두고 엄지 영역이 맵 아래 구석에 반투명으로 겹친다(오른쪽 아래에 괴물 출발점이 있음). 화면 고정 · 전체 맵 보기는 유지한다(줌 · 카메라 따라가기는 PC와 정보량이 달라져 하지 않는다)
   - **적용 시점**: 판 시작 직전, `match`를 받고 가로 · 전체 화면 전환에 따른 크기 변화를 최대 300ms 기다린 뒤 `setGameSize`로 적용한다(세로로 열었다 돌리는 경우). (구현: 세로 안내가 덮는 동안은 세지 않고 가로가 된 때부터 다시 센다 — DECISIONS 'M12: 판 시작 배치 시점') 판 중 크기가 바뀌면 논리 크기는 두고 다시 맞추며 터치 컨트롤만 재배치한다. 새로고침 · Phaser 재생성은 하지 않는다
2. **글자 크기**: 터치 모드 보조 글자 12 CSS px 이상, 주요 글자 14 이상(높이 360 기준). 팀 카드는 실루엣 · 체력 칸 · 상태 아이콘으로 줄인다
3. **안전 영역(노치)**: `viewport-fit=cover`를 넣고 게임 영역 · 터치 컨트롤 · 로비 · 결과 · 토스트 · 깨우기 화면을 `env(safe-area-inset-*)`만큼 안쪽으로
4. **입력 방식별 문구**: 키 이름이 박힌 곳(행동 칸 키캡, 역할 카드 능력 설명, "E로 구조", "아무 키나 누르면 닫힘")을 입력 방식별로. `storyText.ts`와 `STORY_TEXT.md`를 같이
5. **첫 실행 터치 튜토리얼**: 이 기기에서 처음이면(localStorage) 터치 안내 본문을 **판 직전**(준비 후 대기 · 빠른 매칭 대기 · 연습 시작 전)에 보여 준다. 판 중에는 처음 10초 동안 스틱 · 버튼 위치만 입력을 막지 않는 반투명 도형으로 표시한다(화면 가운데 = 감옥 = 생존자 시작 위치를 가리지 않게). 다시 보기는 로비 설정에서. PC는 지금 안내 그대로
6. **성능 목표와 자동 전환(새 그래픽 기준)**
   - 목표: 중급 휴대폰 **품질 중간에서 판 중 평균 50fps 이상**, 저사양 휴대폰 **품질 낮음에서 30fps 이상**. 실기기 확인은 HUMAN_CHECKS
   - M10의 자동 선택 · 판 중 하향을 터치 기기 기준값으로 조정한다(터치 낮음의 해상도 하한 포함). 측정값은 온라인 · 연습을 따로 기억한다
   - 로비 설정에 "진동: 켜기 / 끄기"를 더한다
7. **정적 파일 gzip 압축**: `Accept-Encoding`을 보고 텍스트 자산을 압축해 메모리에 캐시, `Vary: Accept-Encoding`, 이미 압축된 형식(png · woff2)은 그대로
8. **앱 생명주기 · 재접속** (`net.ts`, `app.ts`, 새 `client/src/lifecycle.ts`)
   - 수신 감시: 화면이 보이는 동안 4초간 서버 메시지가 하나도 없으면(서버는 1초마다 pong) 끊고 바로 다시 연결. **숨겨진 동안은 감시를 멈추고**, 다시 보이면 기한을 지금 + 4초로 잡고 즉시 ping을 보내 그 안에 응답이 없을 때만 끊는다(숨김 중 타이머가 멈춰 멀쩡한 소켓을 끊는 오판 방지)

### 자동 검증
- **처리방침 ↔ 코드**: 클라이언트 코드 · public 파일의 저장 키 · 캐시 이름이 모두 `storageKeys.ts`에 있고, 그 목록이 `privacy.html`과 `STORE_LISTING.md` 데이터 보안 절에 모두 나온다. `ClientMessage` 타입에서 뽑은 보내는 필드가 대응표에 빠짐없이 있고, 대응표가 두 문서 모두에 나온다. 서버 로그에 닉네임 0개
- **외부 전송 없음(실제 요청 기준)**: E2E 한 판(혼합 · 연습) 동안 모든 요청과 WebSocket 대상이 같은 출처. 정적 검사는 fetch · WebSocket · src/href 대상만 보고 XML 네임스페이스 같은 문자열은 허용 목록으로
- `/privacy`: 200 · `text/html` · `lang="ko"` · 게임 HTML 아님 · 필수 제목(항목 · 목적 · 보관 · 제3자 · 위탁 · 국외 이전 · 파기 · 권리 · 문의처 · 시행일), 오프라인에서도 열림, 360px 폭에서 가로 스크롤 없음, 로비 링크를 탭하면 열림. `verify:deploy`에도
- `STORE_LISTING.md`: 이름 30자 · 짧은 설명 80자 · 자세한 설명 4000자 이하(한글 1자 = 1자), 등급 답변이 코드와 맞음(채팅 메시지 타입 없음, 결제 · 광고 · 분석 의존성 없음)
- 이미지 규격: 스크린샷 4장 이상 · 각 변 320~3840 · 긴 변 ≤ 짧은 변 × 2 · 알파 없음, 그래픽 정확히 1024×500 · 알파 없음, 아이콘 512×512 · 1MB 이하 · 완전 불투명, 모두 `git ls-files`에 있음, 장면이 서로 다름, 촬영 순간 터치 UI가 보임
- `PLAY_STORE_GUIDE.md`: 요청한 단계 제목이 모두 있고, 적힌 환경변수 이름 · 경로가 서버 코드와 글자 그대로 같음
- 전체 회귀(단위 · 봇 · E2E · 지연 · 배포) + 콘솔 0 → 빠른 검사 CI + 병합 직전 전체 검사 → 병합 → 최종 보고
