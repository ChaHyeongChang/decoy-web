# 사람이 직접 확인할 것

자동 테스트로는 판단할 수 없는 손맛 · 재미 · 밸런스 · 실제 환경 항목이다. 플레이테스트 때 확인하고, 결과를 `docs/playtest/`나 이슈로 남긴다. 수치를 바꿀 때는 `config/balance.json`만 고치면 된다.

## 실제 환경

- [ ] **GPU가 있는 실제 PC에서 브라우저 탭 4개 평균 FPS 55 이상** (WebGL 기본 렌더러). 컨테이너에는 GPU가 없어 Canvas 렌더러(`?renderer=canvas`)로만 자동 측정했다
- [ ] 느린 노트북에서 끊기면 로비의 그래픽 품질을 낮음으로(또는 주소에 `&quality=low`) 바꿔 나아지는지
- [ ] 실제 서비스(Cloud Run · Fly.io · 가상 서버 등)에 배포 후 접속 (`docs/DEPLOY.md`). 이미지 빌드와 컨테이너 접속은 `npm run verify:deploy`로 자동 확인했지만, 계정 · 결제가 필요한 실제 배포는 하지 않았다
- [ ] **Render 무료 플랜 실제 배포** (`docs/DEPLOY.md` 3.4, 계정 필요): 태블릿에서 Blueprint로 서비스 만들기 → Live → `/healthz` ok → 4명 접속. `render.yaml`은 Render 공식 스키마로 검증하지 못했다(작업 환경에서 render.com 접속이 막혀 있었다). Blueprint 화면에서 설정 오류가 뜨면 그 내용대로 고친다
- [ ] **잠든 뒤 깨우기 화면** (15분 넘게 아무도 접속하지 않은 뒤): 처음 여는 기기는 Render 대기 화면 → 게임, 한 번 들어왔던 기기는 DECOY "서버를 깨우는 중…" → 저절로 다시 열림, 잠자기에서 깨어난 기기의 열려 있던 탭은 "서버에 다시 연결하는 중…" → 다시 연결. 방은 사라졌으므로 "새 방을 만들어…" 안내가 뜨는지. 태블릿 · 휴대폰 · 노트북에서 각각. 깨어나는 데 실제로 몇 초 걸리는지 적어 둔다
- [ ] **Render 무료 서버 성능**: 4명 한 판 동안 끊김 · 순간이동이 없는지(`&debug=1`의 서버 틱 · 핑). 무료 인스턴스는 CPU 0.1개다(작업 환경 측정: 4명 한 판에 한 코어의 약 3%). 끊기면 Starter 플랜을 검토한다
- [ ] **싱가포르 리전 핑**(한국에서 70~100ms 예상)에서 조작 체감. 목표(30~60ms)보다 높다
- [ ] 배포 서비스의 WebSocket 연결 시간 제한(예: Cloud Run 60분)에 걸려 끊겼을 때 자동 재접속이 자연스러운지
- [ ] 실제 인터넷 핑(한국 · 일본 리전 30~60ms)에서 조작 체감
- [ ] 발표장 네트워크에서 접속
- [ ] **`docs/PLAY_STORE_GUIDE.md` 1부**(개발자 계정 · 신원 확인 · Android 기기 인증 · 테스터 12명 모으기)를 태블릿으로 따라 하면서 정책 · 금액(등록비 US$25) · 화면 이름이 문서와 맞는지. 작업 환경의 네트워크 제한으로 구글 안내 페이지를 직접 확인하지 못하고 2026년 10월 기준으로 알고 있는 내용으로 썼다. 다르면 문서를 고친다

## 손맛 · 밸런스

- [ ] **회전 감속이 직각 코너에도 걸려야 하는가.** 지금은 문서대로 90° "초과"만 감속한다(반대 방향 꺾기, 135° 꺾기). 기둥을 직각으로 돌 때도 감속하게 하려면 `monster.turnSlowAngle`을 89로 바꾼다
- [ ] **공격 준비 중 괴물 이동 허용**(`monster.attack.windupMoveMultiplier` 1.0)이 적당한가. 피하기 너무 어려우면 0.5나 0으로 낮춘다
- [ ] **거점 지키기 방지 5초**(`capturePoint.monsterBlockGrace`)가 적당한가
- [ ] **lag 200(핑 200ms)에서 괴물 화면의 생존자 "팝인"**: 괴물 화면의 부채꼴 · 안개는 내 조준(예측)으로 바로 그리지만, 그 안의 생존자는 서버가 확인한 뒤에 보내므로 핑만큼 늦게 나타난다. 거슬리면 안개 컷을 서버 조준 기준으로 바꾸는 방법이 있다
- [ ] 생존자 화면에서 괴물 부채꼴을 안개 위에 전체 모양으로 그린 것(DECISIONS D4)이 의도를 읽는 데 도움이 되는지, 오히려 정보가 너무 많은지
- [ ] **효과음 크기 · 느낌** (WebAudio 합성: 공격 준비 · 피격 · 점령 시작 · 완료 · 문 열림 · 포효). 남의 피격은 40% 크기로 낸다. 너무 크거나 거슬리면 `client/src/audio.ts`의 `MASTER_GAIN`을 낮춘다
- [ ] **괴물 기절 중 채도 감소**가 Canvas(`saturation` 합성)와 WebGL(반투명 회색) 렌더러에서 둘 다 "흐려졌다"로 읽히는지
- [ ] **괴물 공격 준비 즉시 표시**(누른 순간 범위 + 소리, 서버 확인 전)가 실제 핑에서 자연스러운지, 서버가 거절했을 때(동시에 밀치기를 맞은 경우 등) 범위가 잠깐 떴다 사라지는 것이 거슬리지 않는지
- [ ] 피격 붉은 플래시(0.2초)와 발각 테두리(지속)가 구분되는지

## M11 터치 조작

`docs/MOBILE_PLAN.md` M11의 "사람이 확인할 것". 실제 안드로이드 휴대폰(가로)과 PC로 확인한다.

- [ ] 이동 · 조준 스틱 손맛: 데드존 15%, 스틱 크기, 누른 자리에 생기는 떠 있는 이동 스틱
- [ ] 괴물 조준 스틱: 놓을 때 발사 대기(최대 0.35초)가 늦게 느껴지지 않는지, 가운데로 되돌려 놓으면 취소되는 것이 자연스러운지, 돌진 버튼을 끌어 방향을 정하는 것
- [ ] **PC와 터치의 유불리** — "PC 괴물 대 휴대폰 생존자"와 "휴대폰 괴물 대 PC 생존자"를 각 3판 하고 승패와 체감을 적는다
  - 터치는 360° 이동, PC는 8방향
  - PC 괴물은 이동하면서 마우스로 아무 데나 보고, 터치 괴물은 오른손으로 조준해야 한다(스틱을 놓으면 이동 방향을 보는 편의)
  - 터치 괴물이 조준을 유지한 채 포효 · 시야 전환을 하기 어려운지, 버튼을 누르려다 스틱을 놓아 공격이 잘못 나가는 빈도
  - 공격 발사 지연(터치 최대 0.35초, PC 클릭은 즉시)
  - 6인치 화면에서 생존자 · 부채꼴 · 안개 경계를 PC만큼 알아보는지, 손가락이 맵을 가리는 정도
  - 진동이 있는 쪽이 발각을 더 빨리 알아채는지(M12)
  - 모바일 데이터 · 백그라운드 끊김 때문에 괴물 정지 규칙(판마다 합계 30초)이 휴대폰 괴물에게 더 자주 걸리는지(M12)
- [ ] 세로로 돌린 동안에도 판은 흐른다(그동안 무방비) — 받아들일 만한지
- [ ] 실기기에서 핀치 · 더블탭 확대 · 길게 눌러 선택 · 당겨서 새로고침 · 가장자리 뒤로 가기 스와이프가 정말 막히는지

## 내 움직임 고르기 (2026-10-24)

휴대폰 120Hz에서 따라가는 카메라(PR #22) 뒤 '봇과 연습'의 내 캐릭터가 툭툭 끊기던 것을 고쳤다(원인 · 고친 것 DECISIONS 10절, 전후 수치 `docs/PERF.md` 5절). 규칙 · 판정 · 수치는 그대로다. 확인은 휴대폰 크롬 탭 `?debug=1`(펼친 표 둘째 줄에 '늦음 %'가 새로 있다).

- [ ] (끊김) 같은 휴대폰 · 기본 프레임 제한(자동)으로 봇과 연습을 하며 네 역할(괴물 · 러너 · 가드 · 스카우트)로 직선 · 대각선으로 걸어 볼 때 내 캐릭터가 툭툭 끊기거나 앞뒤로 흔들리지 않는지. 다른 캐릭터(봇 · 동료)와 같은 정도로 매끄러운지
- [ ] (`?fpsLimit=60`) 60fps · 16.7ms에서도 끊김 · 흔들림이 없는지 (예전에는 이 설정에서도 끊겼다 — 원인이 프레임 수가 아니었다)
- [ ] (120 → 60 자동) 120Hz를 고르게 못 버티는 휴대폰(오버레이 FPS 90~100, '늦음' 15% 이상)에서 판을 15초 넘게 하면 목표가 60으로 내려가는지(오버레이 '목표 60'), 내려간 뒤가 90~100fps일 때보다 매끄러워 보이는지. 120을 고르게 버티는 휴대폰은 목표 120 그대로인지. 고른 60이 오히려 답답하면 기준(`PACING_WATCH.maxLateRatio` 0.15)을 올린다
- [ ] (반응) 키 · 이동 스틱을 누른 순간부터 내 캐릭터가 움직이기까지가 예전보다 늦게 느껴지지 않는지 (컨테이너에서 잰 첫 움직임은 같거나 빨라졌다, PERF 5절)
- [ ] (선명도) 걸을 때 맵 · 글자 · 선이 흐려지지 않는지(맵은 기기 픽셀 격자 그대로, 내 캐릭터만 반 픽셀 안에서 옮겨 그린다)
- [ ] (온라인 지연) 온라인 판(같은 와이파이 · 배포 서버)에서도 내 캐릭터가 매끄러운지, 다른 사람과 부딪히거나 밀칠 때 보정이 한 번에 튀지 않고 부드럽게 맞춰지는지
- [ ] (판 중 순간 멈춤) 판 10초쯤 한 번 화면이 0.5초 넘게 멈추는지 — 컨테이너(SwiftShader)에서는 WebGL 장면마다 GPU 프로세스의 화면 교환이 한 번 0.4~0.7초 걸렸다(메인 스레드 · 텍스처 올리기와 무관, 고치기 전 빌드도 같다, PERF 5절). 실기기에서 보이면 `?debug=1`의 프레임 p95와 함께 알려 준다

- [ ] (설정 화면) 노치 · 펀치홀 휴대폰 가로에서 카드가 노치 쪽 띠에 걸리지 않는지, 주소 표시줄이 나타나고 사라질 때 카드가 잘리지 않는지
- [ ] (UI 크기) '크게' · '아주 크게'에서 로비 · 결과 · 설정 화면 글자가 읽기 좋아지는지, 첫 화면이 스크롤로 다 닿는지, 다음 판 HUD(타이머 · 거점 링 · 팀 카드 · 지도)가 커지면서 엄지 버튼 · 맵과 겹치지 않는지
- [ ] (음량) 전체 · 효과음 · UI 음량 밀대가 손가락으로 조절하기 쉬운지, 음소거가 바로 되는지, 설정 화면 UI 소리(탭 · 고르기 · 열기 · 닫기)가 거슬리지 않는지(기본 60%)
- [ ] (조이스틱) 조이스틱 크기 80~130% · 투명도 0~60%가 다음 판에 반영되는지, 가장 크게 해도 다른 버튼과 겹치지 않는지(겹치면 기본 배치로 돌아간다), 투명도를 높여도 스틱을 찾을 수 있는지
- [ ] (캐릭터 기본값) 새로 설치하거나 브라우저 데이터를 지운 휴대폰에서 첫 화면 연습 역할 고르기 · 방 역할 카드 · 판 속 캐릭터가 새 캐릭터로 시작하는지. 예전에 '기존'을 골라 두었던 휴대폰은 저장값이 없어(예전에는 기본값이라 지웠다) 새 캐릭터로 바뀐다 — 설정에서 다시 '기존'을 고르면 남는다
- [ ] (주소 옵션) `?quality=low` 등으로 연 크롬 탭에서 설정 화면 그 줄에 '주소 옵션이 우선' 노란 안내가 보이고 칸이 잠겨 있는지
- [ ] (조작 배치 편집) 설정 → 조작 → '조작 배치 편집'에서 손가락으로 끄는 느낌이 자연스러운지(손가락에 가려 놓을 자리가 안 보이지 않는지), 떠 있는 명령 판의 자리가 편한지, 막힌 자리 경고(점선 + !)를 알아보는지, 작게 · 크게가 쓸 만한지
- [ ] (조작 배치) 저장한 배치가 다른 휴대폰 크기(16:9 · 20:9 · 21:9) · 태블릿 · 180° 돌림에서도 자연스러운 자리인지, 노치 쪽으로 돌렸을 때 버튼이 노치에 걸리지 않는지
- [ ] (왼손잡이 반전) 좌우 반전에서 이동이 오른쪽 · 버튼이 왼쪽이고 미니맵 · 점수판 · 설정이 왼쪽 위에 오는 배치가 왼손으로 편한지, 화면 밖 화살표가 바뀐 엄지 자리를 피하는지
- [ ] (판 직전 안내) 배치를 바꾼 뒤 '터치 안내 다시 보기'로 본 그림이 내 배치와 맞는지
- [ ] (판 중 설정) 판 중 '설정' 버튼(점수판 왼쪽)을 한 번 탭하면 열리고 바로 닫히지 않는지, 여는 동안 캐릭터가 멈춰 서고(판은 계속) 닫으면 바로 다시 움직이는지, 여는 순간 화면이 끊기지 않는지
- [ ] (지도 크게 보기) 판 중 미니맵을 탭하면 크게 뜨고 아무 데나 탭하면 닫히는지(맵 안 오른쪽 위 미니맵 · 오른쪽 칸 미니맵 둘 다). 흐림은 '남은 문제 정리'에서 고쳤다(아래 절)
- [ ] (번쩍임 · 흔들림 줄이기) 번쩍임 줄이기에서도 맞은 것을 알아볼 수 있는지, 고정된 발각 테두리가 잘 보이는지, 흔들림 줄이기를 켜면 맞을 때 · 포효할 때 화면이 흔들리지 않는지
- [ ] (FPS · 핑 칩) 밝은 바닥 위에서도 읽히는지, 좌우 반전 배치에서 버튼에 가리지 않는지

- [ ] 하드웨어 키보드를 단 태블릿에서 Esc가 같은 동작인지

## 잔렉 고치기 (2026-10-24)

걸을 때 남던 잔렉을 고쳤다(원인 · 고친 것 DECISIONS 12절, 전후 수치 `docs/PERF.md` 6절). 규칙 · 판정 · 수치는 그대로다. 확인은 크롬 탭 `?debug=1`(펼친 표 첫 줄 '목표 · 화면 Hz · 제한', 둘째 줄 '늦음 % · 넘김 %', 셋째 줄 '작업 p95 · 안개 p95').

**PC에서 확인할 것** (모니터 주사율을 먼저 확인: 윈도우 설정 → 디스플레이 → 고급 디스플레이 → 새로 고침 빈도, 또는 오버레이 '화면 NHz')
- [ ] (시야 빛) 품질 높음 · 중간으로 봇과 연습에서 직선으로 걸을 때 내 캐릭터 둘레의 밝은 원 가장자리 · 색 테두리가 몸에 붙어 같이 움직이는지(예전에는 1080p에서 약 22px씩 1초에 20번 뒤처졌다 따라붙었다). 벽 모서리에서 뻗는 그림자 선은 아직 1초에 20번 계단으로 바뀐다 — 거슬리는지
- [ ] (팀원 빛) 팀원 옆을 지나갈 때 두 빛이 겹친 곳이 깜빡이거나 어두워지지 않는지
- [ ] (괴물) 괴물로 걷고 돌진할 때 부채꼴 빛 · 근접 원이 몸을 따라가는지, 돌진 중 벽 너머 바닥이 잠깐 밝아지지 않는지
- [ ] (주사율보다 모자란 fps) 144 · 165Hz 모니터에서 오버레이 FPS가 화면 주사율보다 조금 낮게(예: 100~140) 나오면 판을 15초 넘게 할 때 '목표'가 72 · 82.5로 내려가는지, 내려간 뒤 걸음이 그전보다 고르게 보이는지. 고른 72가 오히려 답답하면 알려 준다(기준 `quality.PACING_WATCH.maxLateRatio` 0.05를 올린다)
- [ ] (프레임 제한) 설정 → 그래픽 → 프레임 제한 '절반'(144Hz → 72, 165Hz → 82.5, 240Hz → 120)과 '60'(144Hz → 72, 165Hz → 55)을 골라 오버레이 '목표'가 그렇게 나오는지, 자동보다 고르게 느껴지는지
- [ ] (격자 맞춤) 주소에 `&camSnap=0`을 붙여 걸어 보고(카메라 창을 기기 픽셀 격자에 맞추지 않음) 맵 스크롤이 더 매끄러운지, 대신 맵 · 글자 · 선이 흐리거나 반짝이는지 — 차이가 있으면 어느 쪽이 나은지 알려 준다
- [ ] (안개 프레임 — 남은 후보) 걷는 동안 오버레이 '넘김'과 '안개 p95'를 적어 준다. 넘김이 1초에 20번 꼴(144Hz 약 14%, 165Hz 약 12% — 안개 다음 프레임의 미니맵까지 늦으면 그 두 배)이거나, 안개 p95 + 약 1ms가 한 vsync(144Hz 6.9ms · 165Hz 6.1ms)를 넘으면 안개 주기 프레임만 늦게 보이는 것이 남은 끊김이다(다음 작업: 안개 일을 여러 프레임에 나누기). 넘김은 하한이다(JS 뒤 paint · commit은 재지 않음) — 0%여도 안개 p95가 vsync의 1ms 안이면 원인일 수 있다. 품질 · 창 크기를 바꾼 직후 몇 초는 다시 굽는 중이라 빼고 본다
- [ ] (반응) 목표가 72 · 82.5로 내려간 뒤 키를 누르고 캐릭터가 움직이기까지가 늦게 느껴지지 않는지(멈춰 있다 움직이기 시작하는 · 멈추는 입력 틱 뒤에는 한 프레임을 바로 그린다), 걷는 중 방향을 바꿀 때 반응이 둔하지 않은지
- [ ] (오르내림) 부하가 오르내리는 PC(144Hz)에서 판 중 목표가 144 ↔ 72로 몇 번 바뀌는 것이 거슬리는지(바뀌는 순간 끊김은 없다. 거슬리면 같은 칸을 다시 내릴 때 올리기를 늦춘다)

**휴대폰에서 확인할 것** (120Hz)
- [ ] (시야 빛) 걸을 때 내 시야 원 · 테두리가 몸에 붙어 움직이는지, 미세한 떨림이 줄었는지
- [ ] (늦은 프레임) 오버레이 '늦음'이 5% 넘게 이어지면 목표가 60으로 내려간다(예전 15%). 내려가는 휴대폰이면 60이 그전보다 고르게 보이는지
- [ ] (안개 프레임) 걷는 동안 오버레이 '넘김'이 약 17%(1초에 20번 ÷ 120)이거나 '안개 p95' + 1ms가 8.3ms를 넘는지 — 그러면 1초에 20번 한 칸씩 늦게 보이는 떨림이 남은 것이다. 품질을 한 단계 내린 뒤(몇 초 기다렸다가) 넘김이 줄어드는지도
- [ ] (반응) 목표가 60으로 내려간 뒤 이동 스틱을 처음 밀 때 · 놓을 때 반응이 예전(120)과 같게 느껴지는지, 스틱을 민 채 방향을 바꿀 때 둔하지 않은지
- [ ] (화면 주사율 바뀜) 배터리 세이버 · 발열로 화면이 120 → 90 · 90 → 60Hz로 바뀌는 휴대폰에서 바뀐 뒤 오버레이 '화면 NHz'가 2~3초 안에 새 값이 되고 움직임이 고른지
- [ ] (90Hz 휴대폰) 고르게 못 버티면 목표가 45로 내려간다(예전 60 — 90Hz의 약수가 아니라 11 · 22ms가 섞였다). 45가 답답한지
- [ ] (GPU 비용) 품질 중간(휴대폰 기본)의 안개 셰이더가 화소마다 계산을 더 한다(컨테이너 소프트웨어 렌더러에서 1080p 10 → 25ms — 실제 GPU는 훨씬 작다고 봄). 예전보다 FPS가 떨어지거나 휴대폰이 더 뜨거워지는지, 오버레이 '늦음'이 늘었는지
- [ ] (품질 낮음) 품질 낮음(Canvas 합성)에서는 시야 빛 · 테두리가 예전처럼 1초에 20번 계단으로 따라간다. 거슬리는지

## 남은 문제 정리 (2026-10-26)

판 중 지도 크게 보기의 흐림, 설정을 닫은 뒤 누르던 이동 키 · 조이스틱을 다시 눌러야 하던 것, 작은 PC 창에서 메뉴 버튼이 팀 카드에 걸치던 것을 고쳤다(DECISIONS 13절, 수치 `docs/PERF.md` 7절). 규칙 · 판정 · 수치는 그대로다.

**휴대폰에서 확인할 것** (안드로이드 크롬 · 설치 앱, 가능하면 아이폰 사파리도)
- [ ] (지도 크게 보기 · 선명도) 품질 낮음 · 중간 · 높음에서 판 중 지도를 탭해 크게 볼 때 벽 윤곽 · 네온 선 · 격자가 또렷한지(예전에는 작은 지도를 늘려 뭉개졌다). 연 직후 몇 프레임(0.2초 안팎)은 예전 그림이었다가 또렷해진다 — 그 바뀜이 거슬리는지
- [ ] (지도 크게 보기 · 끊김) 저사양 휴대폰에서 지도를 여는 순간 · 연 뒤 0.2초 안팎(그 해상도 맵을 나눠 굽고 합성하는 동안) 화면이 끊기지 않는지, 지도를 연 채 걸을 때 FPS가 떨어지지 않는지(`?debug=1` 작업 p95)
- [ ] (지도 크게 보기 · 같은 정보) 괴물로 크게 볼 때 생존자 셋이 모두 같은 흰 모양인지, 크게 본 지도가 작은 지도보다 더 많은 것(시야 밖 생존자 등)을 보이지 않는지
- [ ] (조이스틱 이어받기) 왼손 엄지로 이동 스틱을 민 채 오른손으로 '설정'을 열고 '닫기'를 탭하면, 스틱을 다시 누르지 않아도 그 방향으로 바로 걷는지. 연 동안 엄지를 다른 방향으로 옮겼다면 닫을 때 그 방향으로 걷는지
- [ ] (닫기 탭 · 설정 조작) 스틱을 누른 채 다른 손가락으로 '닫기' · 탭 · 켬끔 단추를 누르면 한 번에 눌리는지(예전에는 두 손가락이면 브라우저가 탭을 무시해 바깥을 눌러야 닫혔다), 두 번 눌린 것처럼 되지 않는지. 밀대(음량)도 두 번째 손가락으로 움직이는지
- [ ] (닫는 입력이 새지 않음) 괴물로 스틱을 누른 채 설정 바깥(어두운 막 — 조준 스틱 자리 포함)을 눌러 닫아도 공격이 나가지 않는지, 생존자로 닫은 직후 능력이 저절로 나가지 않는지
- [ ] (떼고 닫기) 설정을 연 동안 스틱에서 손을 떼고 닫으면 캐릭터가 서 있는지(혼자 걷지 않는지)
- [ ] (HUD 겹침) 800×360 · 915×412 같은 가로 화면에서 괴물 · 생존자 모두 타이머 · 거점 링 · 팀 카드 · 지도 · 설정 · 점수판 · 엄지 버튼이 서로 겹치지 않는지(FPS · 핑 칩을 켠 채로도)

**PC에서 확인할 것**
- [ ] (메뉴 버튼) 960×540 · 1024×576처럼 작은 창에서 '설정 Esc' 버튼이 팀 카드 · 맵에 걸치지 않고 조금 작게 들어가는지, 글자가 읽히는지, 800×600처럼 위아래 여백이 있는 창에서는 캔버스 위 여백에 원래 크기로 뜨는 것이 어색하지 않은지
- [ ] (키 이어받기) W를 누른 채 Esc로 설정을 열었다가 Esc로 닫으면 W를 다시 누르지 않아도 걷는지, 연 동안 D를 더 눌렀다면 대각선으로 걷는지, Space를 누른 채 닫아도 능력이 나가지 않는지
- [ ] (지도 크게 보기) 품질 낮음 · 4K(배율 2) 모니터에서 크게 본 지도가 또렷한지. 4K 품질 높음은 텍스처 예산(32MiB) 때문에 화면 해상도의 약 절반(954px)까지만 올린다 — 여전히 흐리게 보이는지 알려 준다


## 판 평가 · 경험치 · 레벨 (2026-10-27, 메타 a)

## 의상 · 옷장 (2026-10-27, 메타 c)

'내 기록' 창 옷장 탭에서 불씨로 의상을 해금하고 입는다. 생존자 의상은 같은 생존자 팀에만, 괴물 의상은 모두에게 보이고(빠른 매칭은 내 의상만 — 봇 자리 단서가 되지 않게), 괴물 화면에서 생존자는 늘 흰 모습이다(DECISIONS 14절, `GAME_DESIGN.md` 12.5, 값 `config/progression.json` `costumes`). 규칙 · 판정 · 크기 · 보이는 정도는 그대로다.

**휴대폰에서 확인할 것** (안드로이드 크롬 · 설치 앱, 가능하면 아이폰 사파리도)
