# 사람이 직접 확인할 것

자동 테스트로는 판단할 수 없는 손맛 · 재미 · 밸런스 · 실제 환경 항목이다. 플레이테스트 때 확인하고, 결과를 `docs/playtest/`나 이슈로 남긴다. 수치를 바꿀 때는 `config/balance.json`만 고치면 된다.

## 실제 환경

- [ ] **GPU가 있는 실제 PC에서 브라우저 탭 4개 평균 FPS 55 이상** (WebGL 기본 렌더러). 컨테이너에는 GPU가 없어 Canvas 렌더러(`?renderer=canvas`)로만 자동 측정했다
- [ ] 느린 노트북에서 끊기면 로비의 그래픽 품질을 낮음으로(또는 주소에 `&quality=low`) 바꿔 나아지는지
- [ ] 실제 서비스(Cloud Run · Fly.io · 가상 서버 등)에 배포 후 접속 (`docs/DEPLOY.md`). 이미지 빌드와 컨테이너 접속은 `npm run verify:deploy`로 자동 확인했지만, 계정 · 결제가 필요한 실제 배포는 하지 않았다
- [ ] **Render 무료 플랜 실제 배포** (`docs/DEPLOY.md` 3.4, 계정 필요): 태블릿에서 Blueprint로 서비스 만들기 → Live → `/healthz` ok → 4명 접속. `render.yaml`은 Render 공식 스키마로 검증하지 못했다(작업 환경에서 render.com 접속이 막혀 있었다). Blueprint 화면에서 설정 오류가 뜨면 그 내용대로 고친다
- [ ] **잠든 뒤 깨우기 화면** (15분 넘게 아무도 접속하지 않은 뒤): 처음 여는 기기는 Render 대기 화면 → 게임, 한 번 들어왔던 기기는 DECOY "서버를 깨우는 중…" → 저절로 다시 열림, 잠자기에서 깨어난 기기의 열려 있던 탭은 "서버에 다시 연결하는 중…" → 다시 연결. 방은 사라졌으므로 "새 방을 만들어…" 안내가 뜨는지. 태블릿 · 휴대폰 · 노트북에서 각각. 깨어나는 데 실제로 몇 초 걸리는지 적어 둔다
- [ ] **Render 무료 서버 성능**: 4명 한 판 동안 끊김 · 순간이동이 없는지(`&debug=1`의 서버 틱 · 핑). 무료 인스턴스는 CPU 0.1개다(작업 환경 측정: 4명 한 판에 한 코어의 약 3%). 끊기면 Starter 플랜을 검토한다
- [ ] **싱가포르 리전 핑**(한국에서 70~100ms 예상)에서 조작 체감. 목표(30~60ms)보다 높다
- [ ] 배포 서비스의 WebSocket 연결 시간 제한(예: Cloud Run 60분)에 걸려 끊겼을 때 자동 재접속이 자연스러운지
- [ ] 실제 인터넷 핑(한국 · 일본 리전 30~60ms)에서 조작 체감
- [ ] 발표장 네트워크에서 접속
- [ ] **`docs/PLAY_STORE_GUIDE.md` 1부**(개발자 계정 · 신원 확인 · Android 기기 인증 · 테스터 12명 모으기)를 태블릿으로 따라 하면서 정책 · 금액(등록비 US$25) · 화면 이름이 문서와 맞는지. 작업 환경의 네트워크 제한으로 구글 안내 페이지를 직접 확인하지 못하고 2026년 10월 기준으로 알고 있는 내용으로 썼다. 다르면 문서를 고친다

## 손맛 · 밸런스

- [ ] **회전 감속이 직각 코너에도 걸려야 하는가.** 지금은 문서대로 90° "초과"만 감속한다(반대 방향 꺾기, 135° 꺾기). 기둥을 직각으로 돌 때도 감속하게 하려면 `monster.turnSlowAngle`을 89로 바꾼다
- [ ] **공격 준비 중 괴물 이동 허용**(`monster.attack.windupMoveMultiplier` 1.0)이 적당한가. 피하기 너무 어려우면 0.5나 0으로 낮춘다
- [ ] **거점 지키기 방지 5초**(`capturePoint.monsterBlockGrace`)가 적당한가
- [ ] **lag 200(핑 200ms)에서 괴물 화면의 생존자 "팝인"**: 괴물 화면의 부채꼴 · 안개는 내 조준(예측)으로 바로 그리지만, 그 안의 생존자는 서버가 확인한 뒤에 보내므로 핑만큼 늦게 나타난다. 거슬리면 안개 컷을 서버 조준 기준으로 바꾸는 방법이 있다
- [ ] 생존자 화면에서 괴물 부채꼴을 안개 위에 전체 모양으로 그린 것(DECISIONS D4)이 의도를 읽는 데 도움이 되는지, 오히려 정보가 너무 많은지
- [ ] **효과음 크기 · 느낌** (WebAudio 합성: 공격 준비 · 피격 · 점령 시작 · 완료 · 문 열림 · 포효). 남의 피격은 40% 크기로 낸다. 너무 크거나 거슬리면 `client/src/audio.ts`의 `MASTER_GAIN`을 낮춘다
- [ ] **괴물 기절 중 채도 감소**가 Canvas(`saturation` 합성)와 WebGL(반투명 회색) 렌더러에서 둘 다 "흐려졌다"로 읽히는지
- [ ] **괴물 공격 준비 즉시 표시**(누른 순간 범위 + 소리, 서버 확인 전)가 실제 핑에서 자연스러운지, 서버가 거절했을 때(동시에 밀치기를 맞은 경우 등) 범위가 잠깐 떴다 사라지는 것이 거슬리지 않는지
- [ ] 피격 붉은 플래시(0.2초)와 발각 테두리(지속)가 구분되는지

## M10 비주얼 리마스터

- [ ] 분위기가 컨셉(어두운 시설 · 청록 네온 · 붉은 괴물)과 맞는지, 로비 · HUD · 결과가 보기 좋은지

## M11 터치 조작

`docs/MOBILE_PLAN.md` M11의 "사람이 확인할 것". 실제 안드로이드 휴대폰(가로)과 PC로 확인한다.

- [ ] 이동 · 조준 스틱 손맛: 데드존 15%, 스틱 크기, 누른 자리에 생기는 떠 있는 이동 스틱
- [ ] 괴물 조준 스틱: 놓을 때 발사 대기(최대 0.35초)가 늦게 느껴지지 않는지, 가운데로 되돌려 놓으면 취소되는 것이 자연스러운지, 돌진 버튼을 끌어 방향을 정하는 것
- [ ] **PC와 터치의 유불리** — "PC 괴물 대 휴대폰 생존자"와 "휴대폰 괴물 대 PC 생존자"를 각 3판 하고 승패와 체감을 적는다
  - 터치는 360° 이동, PC는 8방향
  - PC 괴물은 이동하면서 마우스로 아무 데나 보고, 터치 괴물은 오른손으로 조준해야 한다(스틱을 놓으면 이동 방향을 보는 편의)
  - 터치 괴물이 조준을 유지한 채 포효 · 시야 전환을 하기 어려운지, 버튼을 누르려다 스틱을 놓아 공격이 잘못 나가는 빈도
  - 공격 발사 지연(터치 최대 0.35초, PC 클릭은 즉시)
  - 6인치 화면에서 생존자 · 부채꼴 · 안개 경계를 PC만큼 알아보는지, 손가락이 맵을 가리는 정도
  - 진동이 있는 쪽이 발각을 더 빨리 알아채는지(M12)
  - 모바일 데이터 · 백그라운드 끊김 때문에 괴물 정지 규칙(판마다 합계 30초)이 휴대폰 괴물에게 더 자주 걸리는지(M12)
- [ ] 세로로 돌린 동안에도 판은 흐른다(그동안 무방비) — 받아들일 만한지
- [ ] 실기기에서 핀치 · 더블탭 확대 · 길게 눌러 선택 · 당겨서 새로고침 · 가장자리 뒤로 가기 스와이프가 정말 막히는지

## M13 혼자서도: 봇과 연습 · 빠른 매칭 · 앱 셸
- [ ] (봇과 연습) 실전 봇이 재밌는 상대인지(너무 강함 · 약함), 봇 괴물이 생존자를 "몰래 아는" 것처럼 느껴지지 않는지(봇은 자기 화면에 보이는 것 · 포효 핑 · 점령 알림만 쓴다), 봇 생존자가 벽에 비비거나 제자리에서 맴돌지 않는지
- [ ] (봇과 연습) 오프라인 연습 판과 온라인 판의 손맛 차이(연습은 지연 0), 휴대폰에서 연습 판 FPS가 온라인 판과 비슷한지(기기 안에서 판정 · 봇 셋을 같이 돌린다)
- [ ] (첫 화면) 서버가 잠들었을 때 첫 화면 상태 줄("서버를 깨우는 중… n초 — 기다리는 동안 봇과 연습을 할 수 있어요")이 눈에 띄는지, 깨어나면 방 만들기 · 입장이 저절로 켜지는지, 연습 역할 고르기(2 × 2 · 낮은 화면 4 × 1) 버튼이 누르기 편한지
- [ ] (결과) 결과 화면 "홈으로"와 "다시 하기"의 자리 · 크기가 헷갈리지 않는지
- [ ] (봇과 연습) 봇끼리 판은 1.5~4.5분으로 사람 판(8~10분 목표)보다 짧다(봇 생존자가 두 거점을 동시에 점령한다). 사람이 섞인 연습 판의 길이 · 긴장감이 괜찮은지
- [ ] (규칙 · 봇 두뇌 작업 중 발견) 거점 지키기 방지(`capturePoint.monsterBlockGrace`)와 감옥 캠핑 시간이 반경 밖으로 한 틱만 나가도 0으로 돌아간다 — 사람 괴물이 들락날락하며 두 벌칙을 피할 수 있는지, 피한다면 "벗어난 뒤 n초가 지나야 초기화"로 바꿀지 판단(규칙 변경이라 GAME_DESIGN · balance 필요)
- [ ] (규칙 · 봇 두뇌 작업 중 발견) 첫 피격 뒤 괴물(5.5)이 생존자(5.0)에 붙은 채 다음 공격까지 따라가 두 번째 피격이 거의 확실하다. 질주 · 밀치기 · 동료의 흩어짐만 이를 끊는다 — 의도한 긴장인지
- [ ] (오프라인 · M13d) 배포 주소를 휴대폰 브라우저로 한 번 연 뒤 비행기 모드로 다시 열기 → 첫 화면 "인터넷 연결이 없어요" + 봇과 연습 한 판, 비행기 모드를 끄면 상태 줄이 "서버 연결됨"으로 바뀌는지
- [ ] (오프라인 · M13d) Render가 잠든 동안(15분 넘게 아무도 없음) 한 번 열어 둔 기기에서 열기 → 깨우기 화면의 "기다리는 동안 봇과 연습"이 보이고 바로 판이 시작되는지, 그사이 서버가 깨면 연습을 끝내고 홈으로 갔을 때 연결되는지
