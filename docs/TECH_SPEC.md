# DECOY v2 기술 설계

## 1. 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (strict) | 서버 · 클라이언트 · 테스트가 같은 시뮬레이션 코드를 공유 |
| 클라이언트 | Phaser 3 + Vite | 2D 렌더링, 입력, 씬 관리. 시야 · 안개는 RenderTexture/마스크로 그린다 |
| 서버 | Node.js 20+ + `ws` | 권한 서버. 판정과 상태를 전부 서버가 가진다 |
| 공유 코드 | `shared/` 워크스페이스 | 이동 · 충돌 · 시야 계산 · 규칙 상수 |
| 테스트 | Vitest (규칙 단위), Node 봇 클라이언트(시나리오), Playwright (브라우저 4개 E2E) |
| 배포 | Dockerfile 하나로 서버가 클라이언트 정적 파일까지 서빙 | 링크 하나로 접속 |

새 라이브러리를 추가할 때는 이유를 `docs/DECISIONS.md`에 한 줄 적는다.

## 2. 폴더 구조

```
decoy-web/
├─ CLAUDE.md
├─ config/balance.json        ← 수치의 원본
├─ docs/
├─ shared/src/
│  ├─ balance.ts              ← balance.json 로드 + 타입
│  ├─ types.ts                ← 엔티티, 메시지 타입

│  ├─ geometry.ts             ← 원-사각 충돌, 레이캐스트, 시야 다각형, 부채꼴 판정
│  ├─ movement.ts             ← 입력 → 이동 (서버와 클라이언트 예측이 같은 함수를 쓴다)
│  └─ visibility.ts           ← "누가 무엇을 볼 수 있는가" 판정
├─ server/src/
│  ├─ index.ts                ← HTTP(정적 파일) + WebSocket
│  ├─ room.ts                 ← 방, 로비, 역할 선택, 재접속
│  ├─ game.ts                 ← 고정 틱 시뮬레이션과 규칙
│  ├─ systems/                ← combat, prison, capture, exit, abilities, match
│  ├─ interest.ts             ← 플레이어별로 볼 수 있는 것만 담은 스냅샷 생성
│  └─ bots.ts                 ← 개발 · 테스트용 봇
├─ client/src/
│  ├─ main.ts, net.ts         ← 연결, 예측 · 보정, 보간
│  ├─ scenes/                 ← Lobby, Game, Result
│  ├─ render/                 ← 맵, 캐릭터, 안개, 부채꼴, 효과
│  ├─ ui/                     ← HUD, 미니맵, 배너, 튜토리얼
│  └─ debug.ts                ← window.__DECOY__ 디버그 훅
└─ tests/
   ├─ unit/                   ← Vitest
   ├─ bots/                   ← 헤드리스 봇 시나리오
   └─ e2e/                    ← Playwright (4 컨텍스트)
```

## 3. 네트워크

### 3.1 원칙
- **서버만 판정한다.** 클라이언트는 입력만 보낸다 (이동 벡터, 조준 각도, 버튼 상태, 입력 번호 `seq`)
- 서버 고정 틱 30Hz, 스냅샷 전송 20Hz. JSON 메시지 (4인 규모라 충분)
- 메시지 타입은 `shared/src/types.ts`에 한 곳에서 정의한다

### 3.2 지연 대응 (처음부터 넣는다)
- **내 캐릭터 예측**: 입력을 보내는 동시에 `shared/movement.ts`로 즉시 움직인다. 스냅샷이 오면 서버가 처리한 마지막 `seq` 이후 입력을 다시 적용해 보정한다
- **다른 캐릭터 보간**: 100ms 지난 시점의 두 스냅샷 사이를 보간해서 그린다
- 공격 · 능력은 예측하지 않는다(서버 확정 후 표시). 대신 버튼을 누른 즉시 준비 모션 효과음/작은 이펙트를 로컬로 보여 반응성을 준다
- **지연 시뮬레이션**: 서버 실행 옵션 `--lag=100` 또는 `?lag=100`으로 송수신에 인위적 지연과 ±20ms 흔들림을 건다. 100ms, 200ms에서 테스트한다

### 3.3 관심 영역 (정보 필터링)
`server/interest.ts`가 플레이어마다 스냅샷을 따로 만든다.

| 받는 쪽 | 포함 | 제외 |
|---|---|---|
| 생존자 | 팀원 전원(항상), 생존자 시야 합집합 안의 괴물과 부채꼴(모드 · 각도), 스카우트 탐지 · 포효 경고 중의 괴물 위치 | 그 밖의 괴물 정보 |
| 괴물 | 자기 상태, 부채꼴 · 근접 원 안 생존자(역할 정보 없이 흰색, 능력 사용 직후 1초만 역할 포함), 포효 중 반경 안 생존자 | 그 밖의 생존자 위치, 역할 정보 |
| 공통 | 거점 게이지 · 상태, 탈출구 상태, 감옥 상태(누가 갇혔는지는 생존자만), 알림 이벤트, 남은 시간 | — |

- 시야 판정은 `shared/visibility.ts` 하나를 서버(필터링)와 클라이언트(안개 그리기)가 같이 쓴다
- **테스트로 보장한다**: 괴물 클라이언트가 받은 모든 스냅샷에 시야 밖 생존자의 좌표가 없어야 한다

### 3.4 방과 접속
- 방 코드 4글자, 링크 `/?room=ABCD`
- 연결이 끊기면 30초 동안 자리를 유지하고, 같은 브라우저(localStorage 토큰)로 돌아오면 이어서 한다
- 괴물이 30초 안에 돌아오지 않으면 판 무효, 생존자는 사망 처리

## 4. 시야 렌더링

- 시야 다각형: 시야 중심에서 벽 모서리 방향으로 레이캐스트해 가시 영역 다각형을 만든다 (반지름 · 부채꼴로 자르기)
- 생존자 화면: 세 다각형을 합쳐 안개 마스크에서 뚫는다. 겹쳐도 밝기가 누적되지 않게 한다. 경계는 바깥 1.2타일 부드럽게
- 괴물 화면: 부채꼴 + 근접 원 다각형. 부채꼴 경계는 하드 컷 (판정 범위와 같은 모양)
- 갱신 주기: 시야 다각형은 0.1초마다 다시 계산, 그 사이는 위치만 따라 이동
- 조건을 만족하지 않는 대상은 **그리지 않는다** (알파 0이 아니라 아예 생성하지 않거나 visible=false). 애초에 서버가 보내지 않는다

## 5. 렌더 순서 (아래 → 위)

1. 배경 `#0B1622`
2. 바닥 `#1B2733`, 장애물 · 기둥 `#3A4552`, 벽 외곽선 `#C8D2DC`
3. 거점 영역 · 탈출구 영역
4. 생존자 시야 원(역할색 12%) / 괴물 근접 원
5. 괴물 부채꼴 (생존자 화면: 노랑/빨강, 괴물 화면: 노랑)
6. 안개 마스크 `#000000`
7. 캐릭터 · 공격 범위 · 효과
8. 항상 표시 배지 (미관측 영역에서는 알파 45%)
9. HUD · 배너 · 미니맵

## 6. 디버그와 테스트 훅

- `window.__DECOY__ = { role, getLocalState(), getLastSnapshot(), fps, ping }` (개발 빌드와 `?debug=1`에서만)
- `?debug=1` 오버레이: FPS, 핑, 서버 틱, 예측 오차
- 서버 `--seed` 옵션으로 무작위 요소 고정
- 봇: `server/bots.ts`가 실제 WebSocket 클라이언트로 접속해 정해진 행동(순찰, 따라가기, 거점 머물기, 구조)을 한다

## 7. 테스트 전략

| 층 | 무엇을 | 예 |
|---|---|---|
| 단위 (Vitest) | 규칙과 수치 | 점령 40초/27초, 수감 2회 후 사망, 3명 동시 수감 시 괴물 승리, 탈출구 2인 3초, 돌진 벽 정지, 캠핑 감속, 보호 4초 피격 무효, 시야 다각형 · 부채꼴 판정 |
| 봇 시나리오 | 서버 규칙 통합 | "유인": 괴물 봇이 러너 봇을 쫓는 동안 다른 봇이 거점 A 완료 / "구조": 두 명 수감 → 한 번에 해방 / "전체 판": 봇 4명으로 한 판 끝까지 |
| E2E (Playwright) | 브라우저 4개 동기화와 정보 차단 | 4 컨텍스트로 방 입장 → 시작 → 각자 이동 → 서로의 위치가 허용된 범위에서 일치 / 괴물 컨텍스트 스냅샷에 숨은 생존자 없음 / 역할별 스크린샷 저장 |
| 지연 | 100ms · 200ms | 내 캐릭터 입력 반응이 즉시인지(예측), 보정 튐이 작은지, 판정 결과가 네 클라이언트에서 같은지 |
| 성능 | 브라우저 4개 동시 | 각 탭 평균 FPS 55 이상 (헤드리스 측정치 기준) |

E2E 스크린샷은 `artifacts/`에 저장하고, 사람이 볼 수 있게 마지막 보고에 경로를 적는다.

## 8. 실행과 배포

- `npm install` → `npm run dev` (서버 + 클라이언트 동시, 핫 리로드)
- `npm run build && npm start` → 포트 8080에서 서버가 클라이언트까지 서빙
- **같은 와이파이 플레이**: `npm start` 후 `http://<내 PC IP>:8080/?room=...`
- **인터넷 플레이**: Dockerfile로 서버를 배포한다. 한국 · 일본 리전을 쓴다(핑 30~60ms 목표). 서비스별 무료 플랜 조건은 바뀌므로 배포 시점에 확인한다. 무료 플랜이 잠드는 서비스라면 테스트 전에 한 번 접속해 깨운다
- 배포는 계정 인증이 필요하므로 Claude는 Dockerfile과 배포 안내(`docs/DEPLOY.md`)까지만 만들고, 실제 배포는 사람이 한다
