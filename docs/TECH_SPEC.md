# DECOY v2 기술 설계

## 1. 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (strict) | 서버 · 클라이언트 · 테스트가 같은 시뮬레이션 코드를 공유 |
| 클라이언트 | Phaser 3 + Vite | 2D 렌더링, 입력, 씬 관리. 시야 · 안개는 빛 지도를 바닥에 곱해서 그린다(Canvas 렌더러는 Canvas2D 한 장 합성, WebGL은 GPU 합성 — 4장) |
| 서버 | Node.js 20+ + `ws` | 권한 서버. 판정과 상태를 전부 서버가 가진다 |
| 공유 코드 | `shared/` 워크스페이스 | 이동 · 충돌 · 시야 계산 · 규칙 상수 |
| 테스트 | Vitest (규칙 단위), Node 봇 클라이언트(시나리오), Playwright (브라우저 4개 E2E) |
| 배포 | Dockerfile 하나로 서버가 클라이언트 정적 파일까지 서빙 | 링크 하나로 접속 |

새 라이브러리를 추가할 때는 이유를 `docs/DECISIONS.md`에 한 줄 적는다.

## 3. 네트워크

### 3.1 원칙
- **서버만 판정한다.** 클라이언트는 입력만 보낸다 (이동 벡터, 조준 각도, 버튼 상태, 입력 번호 `seq`)
- 서버 고정 틱 30Hz, 스냅샷 전송 20Hz. JSON 메시지 (4인 규모라 충분)
- 메시지 타입은 `shared/src/types.ts`에 한 곳에서 정의한다

### 3.2 지연 대응 (처음부터 넣는다)
- **내 캐릭터 예측**: 입력을 보내는 동시에 `shared/movement.ts`로 즉시 움직인다. 스냅샷이 오면 서버가 처리한 마지막 `seq` 이후 입력을 다시 적용해 보정한다
- **내 캐릭터 그리기** (내 움직임 고르기, DECISIONS 10절): 그리는 자리 = 직전 · 지금 입력 틱 상태를 그 틱의 **명목 시각**(1/30초 격자, 타이머가 늦게 깬 시각이 아니다)부터 틱 길이 동안 보간한 자리 + 보정 어긋남. 늦게 깬 입력 틱은 렌더 프레임이 먼저 처리한다. 보정 때 다시 적용할 입력이 없어도 보간 구간을 잇고(직전 상태를 보정량만큼 옮김), 어긋남은 그 순간 그린 자리끼리의 차이로 잡아 `correctionSmoothMs` 동안 줄인다. 내 자리 · 카메라는 그 프레임의 rAF 시각(vsync)으로 재고, 카메라는 같은 프레임의 그 자리를 따라간다
- **다른 캐릭터 보간**: 100ms 지난 시점의 두 스냅샷 사이를 보간해서 그린다
- 공격 · 능력은 예측하지 않는다(서버 확정 후 표시). 대신 버튼을 누른 즉시 준비 모션 효과음/작은 이펙트를 로컬로 보여 반응성을 준다
- **지연 시뮬레이션**: 서버 실행 옵션 `--lag=100` 또는 `?lag=100`으로 송수신에 인위적 지연과 ±20ms 흔들림을 건다. 100ms, 200ms에서 테스트한다

### 3.3 관심 영역 (정보 필터링)
`shared/src/sim/interest.ts`가 플레이어마다 스냅샷을 따로 만든다.

| 받는 쪽 | 포함 | 제외 |
|---|---|---|
| 생존자 | 팀원 전원(항상), 생존자 시야 합집합 안의 괴물과 부채꼴(모드 · 각도), 스카우트 탐지 · 포효 경고 중의 괴물 위치 | 그 밖의 괴물 정보 |
| 괴물 | 자기 상태, 부채꼴 · 근접 원 안 생존자(역할 정보 없이 흰색, 능력 사용 직후 1초만 역할 포함), 포효 중 반경 안 생존자 | 그 밖의 생존자 위치, 역할 정보 |
| 공통 | 거점 게이지 · 상태, 탈출구 상태, 감옥 상태(누가 갇혔는지는 생존자만), 알림 이벤트, 남은 시간 | — |
| 판 결과 (메타) | 받는 사람 **자기** 판 평가(`result.rating`, 판이 끝날 때 한 번) | 남의 평가 · 레벨(판이 끝난 뒤에도), 판 중의 평가 · 레벨 · 판 기록 |
| 의상 (메타 c) | 판 시작 명단(`match.info.roster[].costume`, 기본이면 칸 없음): 생존자 명단에 생존자 넷의 그 역할 의상(동료 · 괴물), 괴물 명단은 자기 하나뿐. 빠른 매칭은 자기 의상만 | 괴물에게 생존자 의상(판 시작 명단에 생존자가 없다), 로비 · 결과 · 스냅샷의 의상 칸(누구에게도), 빠른 매칭의 남의 의상(봇 자리는 늘 기본이라 사람 단서) |

- 시야 판정은 `shared/visibility.ts` 하나를 서버(필터링)와 클라이언트(안개 그리기)가 같이 쓴다
- **테스트로 보장한다**: 괴물 클라이언트가 받은 모든 스냅샷에 시야 밖 생존자의 좌표가 없어야 한다

### 3.4 방과 접속
- 방 코드 4글자, 링크 `/?room=ABCD`
- 연결이 끊기면 30초 동안 자리를 유지하고, 같은 브라우저(localStorage 토큰)로 돌아오면 이어서 한다
- 괴물이 30초 안에 돌아오지 않으면 판 무효, 생존자는 사망 처리

### 3.5 판 밖 성장 · 보상 (메타, GAME_DESIGN 12장)

- **판 기록**: 방(`room.ts`)이 판마다 `MatchRecorder`를 만들고 `game.step()` 뒤 틱마다 상태를 보인다. 기록기는 상태를 **읽기만** 하고 난수를 쓰지 않는다(규칙 골든 해시 · 봇 판 그대로 — 단위 시험이 켜고 끈 판의 상태를 견준다). 시야가 필요한 수치는 방이 스냅샷 틱에 이미 계산한 시야 사실(`VisibilityFacts`)로만 센다
- **평가**: 판이 끝나는 틱에 `rateMatch`(공용)로 사람 자리마다 평가를 만들어 `resultFor`가 받는 사람 자기 것만 결과에 싣는다(`buildResult`는 그대로 — 골든 해시). 판 ID = 방 코드 · 판 번호 · 끝난 시각(새 난수 없음). 결과 단계에 다시 붙으면 같은 평가를 다시 보낸다
- **보상**: 지금은 클라이언트가 `applyRating`(공용 순수 함수)으로 경험치를 적립하고 `ProfileStore`(지금은 `DeviceProfileStore` — `decoy:progress`)에 저장한다. 적립 직전에 저장소를 다시 읽어 다른 탭의 적립을 덮지 않는다(저장에 실패해 메모리에만 있는 적립이 있으면 다시 읽지 않는다 — 읽기만 되는 저장소에서 옛 기록으로 돌아가지 않게). 다음 단계 서버 저장은 같은 함수 · 같은 형식으로 서버가 적립하고 `ServerProfileStore`를 끼운다
- **수치**: `config/progression.json`을 서버 · 클라이언트가 빌드에 넣는다(판정 수치가 아니라 `balance.json`과 따로). 모양 검사는 서버 시작 · 단위 시험
- **불씨 · 일일 도전 · 접속 보상**(b): `applyRating`이 그날 날짜 글을 받아 도전 진행 · 불씨까지 적립하고, 접속 보상은 `claimLogin`(하루 한 번, 연속 날). 날짜 글은 클라이언트가 기기 시계로 만든다(`meta.ts localDay`, 자정 기준) — 자정 + 1초 타이머와 앱으로 돌아올 때 칩 · 창을 다시 그린다. 접속 보상은 자동으로 주지 않고 '내 기록' 창에서 받는다(부팅 때 저장소에 쓰지 않는다)
- **의상**(c): 고른 의상(팀마다 하나)을 `join.costume` · `quick.costume` · 판 밖 `costume` 메시지로 보낸다. 서버(`room.ts`)는 id만 거르고(`sanitizeCostumeChoice`, 모르는 값 = 기본) 자리에 두며, 판 중에는 바꾸지 않는다(다시 들어와도 판 시작 의상). 봇 자리는 기본. 판 시작 명단에만 싣고(`matchInfo` — 위 3.3 표) 클라이언트는 그 명단으로 굽기 의상을 정한다(`costumeBake.ts`). 괴물 클라이언트는 생존자 의상을 받지 않으니 굽지도 않고, 괴물 화면 공통 생존자 그림은 의상 인자가 없다(`CommonArtOptions.costume?: never`)
- **같은 칸 바꿔 굽기**(c): 의상은 그 역할 프레임을 같은 이름 · 같은 칸 · 같은 상자로 다시 그린다 — 텍스처 크기 그대로. 판 시작 명단 · 늦게 온 의상 그림으로 의상만 바뀌면 그 주인 칸만 지우고 다시 그려 같은 텍스처 키로 다시 올린다(`atlas.ts recostumeAtlas`, 리그를 다시 만들지 않는다). 기존 캐릭터 스타일에는 의상이 없다
- **나눠 받기**: 결과 화면 코드(`ui/result.ts` · `ui/resultRating.ts`)와 '내 기록' 창(`ui/hub.ts`)은 동적 import 조각이다. 첫 화면을 그린 뒤 판 밖 쉬는 시간에 미리 받고(판 중에는 받지 않는다), 받지 못하면 승리 팀 · 버튼만 있는 작은 결과 + "새 버전이 있어요"(서비스 워커가 옛 셸 캐시를 바로 지우므로 배포 직후 옛 화면이 사라진 조각을 찾을 수 있다). 적립은 첫 묶음 코드가 하므로 조각 실패와 무관하다. 의상 그림(조각 `art`)과 옷장(조각 `wardrobe`, 옷장 탭을 열 때)도 같다 — 의상 그림을 받지 못하면 기본 그림으로 굽고(장식뿐이라 판은 같다) 해금 · 입기는 된다. 첫 묶음은 한 조각이다(`vite.config.ts` codeSplitting `$initial` — 나눠 받는 조각이 첫 묶음 모듈을 함께 써도 첫 묶음을 공용 조각으로 쪼개지 않는다)

## 4. 시야 렌더링

- 시야 다각형: 시야 중심에서 벽 모서리 방향으로 레이캐스트해 가시 영역 다각형을 만든다 (반지름 · 부채꼴로 자르기)
- **안개 = 밝기 하한 + 시야 안 밝게** (M10, GAME_DESIGN 3.1): 빛 지도의 바탕은 검정이 아니라 어두운 청회색 밝기 하한이다(값은 그래픽 상수 + VISUAL_SPEC). 그래서 시야 밖에서도 맵 구조(벽 · 바닥 · 기둥 · 감옥 · 거점 · 탈출구)가 어둡게 보이고, 시야 안은 하한의 2.5배 이상 밝다. 안개는 정보 차단 수단이 아니다: 숨은 상대가 안 보이는 것은 서버가 보내지 않아서이고(3.3), 캐릭터 · 마커는 안개와 곱하지 않고 그 위에 그린다
- **안개 주기와 내 빛 따라가기** (잔렉 고치기, DECISIONS 12절): 빛 지도 · 시야 다각형은 안개 주기(생존자 50ms · 괴물 1/30초)마다만 다시 만들고, 그 사이 프레임은 내 시야 빛 · 틴트 · 테두리 · 괴물 외곽선 · 먼지를 지금 그린 내 자리까지 옮겨 그린다(Δ = 지금 자리 − 주기의 내 눈, `render/fogMath.ts` followShift). GPU 안개(품질 높음 · 중간)는 빛 지도의 '내 덮임' 표시(B 채널)와 셰이더(`followLight`)로, Canvas 합성 · 정밀도가 모자란 셰이더는 옮기지 않는다(예전 그림). 그리는 것만 바뀌고 시야 판정 · 정보 차단은 그대로다
- 생존자 화면: 세 다각형을 빛 지도에 최댓값(`lighten`)으로 그린다(겹쳐도 밝기가 누적되지 않음). 경계는 판정 반경 **안쪽** 1.2타일에서 부드럽게 하한으로 이어진다. 밝게 그린 곳은 항상 판정 영역 안이다(빛 지도 해상도에 따른 경계 1텍셀 이내의 안티에일리어싱은 제외, 괴물 경계는 판정 모양 그대로 벡터 선으로 표시). 빛 지도가 칠하는 경로 · 반지름 · 색은 기록용 컨텍스트로 단위 테스트한다(`tests/unit/fog-paint.test.ts`)
- 괴물 화면: 부채꼴 + 근접 원 다각형. 부채꼴 경계는 하드 컷 (판정 범위와 같은 모양). 딱 잘려야 하는 경계는 빛 지도 해상도에 기대지 않고 판정 모양 그대로 벡터 선으로 덧그린다
- 합성 경로 두 가지 (품질 단계가 고른다, `client/src/gfx/presets.ts`)
  - **Canvas 합성**: 정적 맵 + 공개 동적 레이어(거점 · 탈출구 링, 시야 원) + 빛 지도를 Canvas2D 한 장에 `multiply`로 합성한다. Canvas 렌더러와 품질 낮음. 비용이 픽셀 수에 비례하므로 합성 캔버스 배율은 품질 상한을 따른다
  - **GPU 합성**: 정적 맵 텍스처는 목표 해상도로 한 번만 올리고, 작은 빛 텍스처만 갱신해 곱한다. WebGL의 품질 중간 · 높음. 높음은 가장자리 셰이더를 더한다(어둡게만 — 판정 밖을 밝히지 않음)
  - 두 경로의 밝기 차는 ±3 이내(E2E). 미니맵도 같은 방식
- **렌더 해상도** = 표시 CSS 크기 × min(기기 픽셀 배율, 품질 단계 상한, 픽셀 수 상한) (`client/src/render/resolution.ts`). 논리 좌표 1920×1080은 카메라 zoom으로 유지하고, 캔버스는 기기 픽셀 격자에 맞춰 놓는다. 글자 텍스처 해상도 = zoom. 창 크기 · 기기 픽셀 배율이 바뀌면(모니터 이동 · 브라우저 확대) 다시 맞춘다. `?scale`(0.25~1)은 이 해상도에 곱한다
- 갱신 주기: 빛 지도는 생존자 화면 20Hz, 괴물 화면 30Hz로 다시 그린다(DECISIONS "화면"). 그 사이는 위치만 따라 이동
- 조건을 만족하지 않는 대상은 **그리지 않는다** (알파 0이 아니라 아예 생성하지 않거나 visible=false). 애초에 서버가 보내지 않는다
- 상대에게서 나오는 효과(잔상 · 파티클)는 지금 그린 엔티티를 따라가거나 받은 이벤트 좌표에서만 생기고, 출처가 사라지면 즉시 없앤다

## 6. 디버그와 테스트 훅

- `window.__DECOY__ = { role, getLocalState(), getLastSnapshot(), fps, ping }` (개발 빌드와 `?debug=1`에서만)

- M10 그래픽 검사 훅: `gfx`(렌더 해상도 · 품질 · 안개 방식 · 프레임 제한 · 화면 주사율 · 목표 FPS · 내림 · 올림 횟수), `freezeClock`(장식 애니메이션 시계 고정), `injectFps`(품질 자동 하향 시험), `probeText`(선명도 탐침).
- 렌더링 최적화 훅: `getFrameStats()`(최근 1초 FPS · 프레임 간격 · 작업 시간 평균 · p95 · 그리기 호출 · 건너뛴 rAF, `gfx/frameStats.ts`), `getAnimState()`(보간 · 연출 · 걷기 상태, 60 · 120Hz 프레임 독립성 E2E가 같은 시각끼리 견준다), `setFrameLimit(limit)`(프레임 제한 'auto' · '60' · '120' · 'half' 바꾸기, 저장은 로비 설정만), `setFogFollowDisabled(off)`(내 빛 따라가기 끄기 — 같은 빌드에서 예전 그림과 화소 비교). 진단 주소 `?camSnap=0`은 따라가는 카메라 창을 기기 픽셀 격자에 맞추지 않는다(저장하지 않음). 캐릭터 리디자인: `setCharStyle(style)`(캐릭터 스타일 'classic' · 'new' 바꾸기, 저장하지 않음 — 판 중이면 다음 프레임에 그림을 다시 굽는다), `gfx.charStyle`. 주소 `?chars=new|classic`은 이번 접속만. 타입은 `shared/src/debugTypes.ts`. 리마스터 전후 비교 촬영은 `npm run shots:remaster`(`scripts/remaster-shots.mjs`)
- 서버 `--seed` 옵션으로 무작위 요소 고정
- 봇: `server/bots.ts`가 실제 WebSocket 클라이언트로 접속해 정해진 행동(순찰, 따라가기, 거점 머물기, 구조)을 한다

## 8. 실행과 배포

- `npm install` → `npm run dev` (서버 + 클라이언트 동시, 핫 리로드)
- `npm run build && npm start` → 포트 8080에서 서버가 클라이언트까지 서빙
- **같은 와이파이 플레이**: `npm start` 후 `http://<내 PC IP>:8080/?room=...`
- **인터넷 플레이**: Dockerfile로 서버를 배포한다. 한국 · 일본 리전을 쓴다(핑 30~60ms 목표). 서비스별 무료 플랜 조건은 바뀌므로 배포 시점에 확인한다. 무료 플랜이 잠드는 서비스라면 테스트 전에 한 번 접속해 깨운다
- 배포는 계정 인증이 필요하므로 Claude는 Dockerfile과 배포 안내(`docs/DEPLOY.md`)까지만 만들고, 실제 배포는 사람이 한다
- **그래픽 품질 높음 · 중간 · 낮음** (`?quality=high|medium|low` > 로비에서 고른 값 > 자동). 느린 PC는 로비의 그래픽 품질을 낮음으로(또는 주소에 `&quality=low`). 자동은 Canvas 렌더러 · 소프트웨어 WebGL이면 낮음, 하드웨어 WebGL PC는 높음(PC는 코어 수 · 메모리로 내리지 않는다). 판 중 FPS가 오래 낮으면 한 번 한 단계 내린다. `?scale`은 해상도 배율(0.25~1, 빈 값 · 0 · 음수 · 숫자 아님은 무시)이고 옛 `&scale=0.5` 링크도 "가볍게"로 계속 동작한다
