# DECOY v2 기술 설계

## 1. 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (strict) | 서버 · 클라이언트 · 테스트가 같은 시뮬레이션 코드를 공유 |
| 클라이언트 | Phaser 3 + Vite | 2D 렌더링, 입력, 씬 관리. 시야 · 안개는 빛 지도를 바닥에 곱해서 그린다(Canvas 렌더러는 Canvas2D 한 장 합성, WebGL은 GPU 합성 — 4장) |
| 서버 | Node.js 20+ + `ws` | 권한 서버. 판정과 상태를 전부 서버가 가진다 |
| 공유 코드 | `shared/` 워크스페이스 | 이동 · 충돌 · 시야 계산 · 규칙 상수 |
| 테스트 | Vitest (규칙 단위), Node 봇 클라이언트(시나리오), Playwright (브라우저 4개 E2E) |
| 배포 | Dockerfile 하나로 서버가 클라이언트 정적 파일까지 서빙 | 링크 하나로 접속 |

새 라이브러리를 추가할 때는 이유를 `docs/DECISIONS.md`에 한 줄 적는다.

```

├─ config/balance.json        ← 수치의 원본
├─ docs/
├─ shared/src/

│  ├─ types.ts                ← 엔티티, 메시지 타입

│  ├─ geometry.ts             ← 원-사각 충돌, 레이캐스트, 시야 다각형, 부채꼴 판정

│     ├─ room.ts              ← 방, 로비, 역할 선택, 재접속
│     ├─ game.ts · state.ts   ← 고정 틱 시뮬레이션과 규칙, 서버 상태 타입
│     ├─ systems/             ← combat, prison, capture, exit, abilities, match, monster
│     ├─ interest.ts          ← 플레이어별로 볼 수 있는 것만 담은 스냅샷 생성
│     ├─ botBrains.ts · pathfind.ts · predict.ts ← 봇 두뇌(자기 스냅샷만), 길찾기, 봇의 내 위치 예측
│     ├─ simMatch.ts · truth.ts ← 소켓 없는 봇 판(테스트), 테스트 전용 정답 상태
│     └─ random.ts            ← 자리 토큰 · 임시 ID (Web Crypto `globalThis.crypto`)
├─ server/src/                ← Node 전용 바깥 일만 (shared에는 `node:*` · `ws` · `fs` import 금지, eslint)
│  ├─ index.ts                ← HTTP(정적 파일 · 테스트 훅) + ws 소켓 + setInterval → ServerCore
│  ├─ config.ts · static.ts   ← 실행 옵션 · balance.json 읽기, 정적 파일(gzip)
│  ├─ quickBots.ts            ← 빠른 매칭 같은 프로세스 실전 봇 드라이버(시작 때 실전 봇 지도 준비)
│  ├─ sendPolicy.ts           ← 연결별 송신 큐 · 밀림 처리
│  ├─ truthLog.ts             ← 정답 상태 파일 기록 (--truth-log)
│  └─ bots.ts                 ← 개발 · 테스트용 WebSocket 봇
├─ client/src/
│  ├─ main.ts, net.ts         ← 연결, 예측 · 보정, 보간
│  ├─ scenes/                 ← Lobby, Game, Result
│  ├─ render/                 ← 맵, 캐릭터, 안개, 부채꼴, 효과
│  ├─ ui/                     ← HUD, 미니맵, 배너, 튜토리얼
│  └─ debug.ts                ← window.__DECOY__ 디버그 훅
```

## 3. 네트워크

### 3.1 원칙
- **서버만 판정한다.** 클라이언트는 입력만 보낸다 (이동 벡터, 조준 각도, 버튼 상태, 입력 번호 `seq`)
- 서버 고정 틱 30Hz, 스냅샷 전송 20Hz. JSON 메시지 (4인 규모라 충분)
- 메시지 타입은 `shared/src/types.ts`에 한 곳에서 정의한다

### 3.2 지연 대응 (처음부터 넣는다)
- **내 캐릭터 예측**: 입력을 보내는 동시에 `shared/movement.ts`로 즉시 움직인다. 스냅샷이 오면 서버가 처리한 마지막 `seq` 이후 입력을 다시 적용해 보정한다
- **다른 캐릭터 보간**: 100ms 지난 시점의 두 스냅샷 사이를 보간해서 그린다
- 공격 · 능력은 예측하지 않는다(서버 확정 후 표시). 대신 버튼을 누른 즉시 준비 모션 효과음/작은 이펙트를 로컬로 보여 반응성을 준다
- **지연 시뮬레이션**: 서버 실행 옵션 `--lag=100` 또는 `?lag=100`으로 송수신에 인위적 지연과 ±20ms 흔들림을 건다. 100ms, 200ms에서 테스트한다

### 3.3 관심 영역 (정보 필터링)
`shared/src/sim/interest.ts`가 플레이어마다 스냅샷을 따로 만든다.

| 받는 쪽 | 포함 | 제외 |
|---|---|---|
| 생존자 | 팀원 전원(항상), 생존자 시야 합집합 안의 괴물과 부채꼴(모드 · 각도), 스카우트 탐지 · 포효 경고 중의 괴물 위치 | 그 밖의 괴물 정보 |
| 괴물 | 자기 상태, 부채꼴 · 근접 원 안 생존자(역할 정보 없이 흰색, 능력 사용 직후 1초만 역할 포함), 포효 중 반경 안 생존자 | 그 밖의 생존자 위치, 역할 정보 |
| 공통 | 거점 게이지 · 상태, 탈출구 상태, 감옥 상태(누가 갇혔는지는 생존자만), 알림 이벤트, 남은 시간 | — |

- 시야 판정은 `shared/visibility.ts` 하나를 서버(필터링)와 클라이언트(안개 그리기)가 같이 쓴다
- **테스트로 보장한다**: 괴물 클라이언트가 받은 모든 스냅샷에 시야 밖 생존자의 좌표가 없어야 한다

### 3.4 방과 접속
- 방 코드 4글자, 링크 `/?room=ABCD`
- 연결이 끊기면 30초 동안 자리를 유지하고, 같은 브라우저(localStorage 토큰)로 돌아오면 이어서 한다
- 괴물이 30초 안에 돌아오지 않으면 판 무효, 생존자는 사망 처리

## 4. 시야 렌더링

- 시야 다각형: 시야 중심에서 벽 모서리 방향으로 레이캐스트해 가시 영역 다각형을 만든다 (반지름 · 부채꼴로 자르기)
- **안개 = 밝기 하한 + 시야 안 밝게** (M10, GAME_DESIGN 3.1): 빛 지도의 바탕은 검정이 아니라 어두운 청회색 밝기 하한이다(값은 그래픽 상수 + VISUAL_SPEC). 그래서 시야 밖에서도 맵 구조(벽 · 바닥 · 기둥 · 감옥 · 거점 · 탈출구)가 어둡게 보이고, 시야 안은 하한의 2.5배 이상 밝다. 안개는 정보 차단 수단이 아니다: 숨은 상대가 안 보이는 것은 서버가 보내지 않아서이고(3.3), 캐릭터 · 마커는 안개와 곱하지 않고 그 위에 그린다
- 생존자 화면: 세 다각형을 빛 지도에 최댓값(`lighten`)으로 그린다(겹쳐도 밝기가 누적되지 않음). 경계는 판정 반경 **안쪽** 1.2타일에서 부드럽게 하한으로 이어진다. 밝게 그린 곳은 항상 판정 영역 안이다(빛 지도 해상도에 따른 경계 1텍셀 이내의 안티에일리어싱은 제외, 괴물 경계는 판정 모양 그대로 벡터 선으로 표시). 빛 지도가 칠하는 경로 · 반지름 · 색은 기록용 컨텍스트로 단위 테스트한다(`tests/unit/fog-paint.test.ts`)
- 괴물 화면: 부채꼴 + 근접 원 다각형. 부채꼴 경계는 하드 컷 (판정 범위와 같은 모양). 딱 잘려야 하는 경계는 빛 지도 해상도에 기대지 않고 판정 모양 그대로 벡터 선으로 덧그린다
- 합성 경로 두 가지 (품질 단계가 고른다, `client/src/gfx/presets.ts`)
  - **Canvas 합성**: 정적 맵 + 공개 동적 레이어(거점 · 탈출구 링, 시야 원) + 빛 지도를 Canvas2D 한 장에 `multiply`로 합성한다. Canvas 렌더러와 품질 낮음. 비용이 픽셀 수에 비례하므로 합성 캔버스 배율은 품질 상한을 따른다
  - **GPU 합성**: 정적 맵 텍스처는 목표 해상도로 한 번만 올리고, 작은 빛 텍스처만 갱신해 곱한다. WebGL의 품질 중간 · 높음. 높음은 가장자리 셰이더를 더한다(어둡게만 — 판정 밖을 밝히지 않음)
  - 두 경로의 밝기 차는 ±3 이내(E2E). 미니맵도 같은 방식
- **렌더 해상도** = 표시 CSS 크기 × min(기기 픽셀 배율, 품질 단계 상한, 픽셀 수 상한) (`client/src/render/resolution.ts`). 논리 좌표 1920×1080은 카메라 zoom으로 유지하고, 캔버스는 기기 픽셀 격자에 맞춰 놓는다. 글자 텍스처 해상도 = zoom. 창 크기 · 기기 픽셀 배율이 바뀌면(모니터 이동 · 브라우저 확대) 다시 맞춘다. `?scale`(0.25~1)은 이 해상도에 곱한다
- 갱신 주기: 빛 지도는 생존자 화면 20Hz, 괴물 화면 30Hz로 다시 그린다(DECISIONS "화면"). 그 사이는 위치만 따라 이동
- 조건을 만족하지 않는 대상은 **그리지 않는다** (알파 0이 아니라 아예 생성하지 않거나 visible=false). 애초에 서버가 보내지 않는다
- 상대에게서 나오는 효과(잔상 · 파티클)는 지금 그린 엔티티를 따라가거나 받은 이벤트 좌표에서만 생기고, 출처가 사라지면 즉시 없앤다

## 5. 렌더 순서 (아래 → 위)

자세한 순서와 깊이 값은 VISUAL_SPEC 7.4가 원본이다. 여기에는 큰 묶음만 적는다.

1. 배경 `#0B1622`
2. **월드**(`fogRoot`): 바닥 · 벽 · 시설 발광 · 거점 · 탈출구 영역 · 시야 채움 → 안개(빛 지도 곱하기. 시야 밖은 검정이 아니라 밝기 하한이라 어둡게 남는다, VISUAL_SPEC 3.2). 색은 VISUAL_SPEC 2.3 · 2.4
3. 기절 회색 막 (괴물 화면, 기절 중)
4. 바닥 정보: 항상 표시 배지 · A/B 글자 (캐릭터 **아래**, VISUAL_SPEC R1)
5. 부채꼴 채움 (생존자 화면 노랑/빨강, 괴물 화면 노랑. 안개와 곱하지 않는다, DECISIONS D4) · 공격 준비 채움
6. **엔티티**: 그림자 · 이벤트 효과 · 범위 선 · 마커 · 캐릭터 (안개 · 후처리 없음)
7. **장면 위**: 발각 테두리 · 미니맵 · HUD · 배너 · 조작 안내 · 점수판

블룸 · 비네트 · 색보정은 월드(2)에만 건다(카메라에 걸면 HUD 글자까지 번진다). 품질 단계는 장식만 바꾸고 3~7은 모든 단계에서 같다

## 6. 디버그와 테스트 훅

- `window.__DECOY__ = { role, getLocalState(), getLastSnapshot(), fps, ping }` (개발 빌드와 `?debug=1`에서만)
- `?debug=1` 오버레이 (`client/src/ui/debugOverlay.ts`, 배포 빌드에서도 뜬다): FPS · 목표 · 화면 주사율 · 프레임 제한, 프레임 간격 · 작업 시간(평균 · p95), 그리기 호출(WebGL 호출 수 · Canvas는 그린 객체 수, 이 오버레이를 켰을 때만 센다), 핑 · 서버 틱 · 스냅샷, 예측 오차 · 대기 입력, 품질 · 자동 조정, DPR · 백버퍼, 렌더러 · 입력 방식 · 밸런스 해시. 칩을 눌러 접고 펼친다(터치 기기는 접은 채, PC는 펼친 채 시작, 저장하지 않음). 칩만 입력을 받고 판 입력으로 보내지 않는다. 터치 기기의 칩은 맵 왼쪽 위(판 HUD · 터치 대상과 겹치지 않음, `tests/e2e/debug-overlay.spec.ts`)
- M10 그래픽 검사 훅: `gfx`(렌더 해상도 · 품질 · 안개 방식), `freezeClock`(장식 애니메이션 시계 고정), `injectFps`(품질 자동 하향 시험), `probeText`(선명도 탐침). 타입은 `shared/src/debugTypes.ts`. 리마스터 전후 비교 촬영은 `npm run shots:remaster`(`scripts/remaster-shots.mjs`)
- 서버 `--seed` 옵션으로 무작위 요소 고정
- 봇: `server/bots.ts`가 실제 WebSocket 클라이언트로 접속해 정해진 행동(순찰, 따라가기, 거점 머물기, 구조)을 한다

## 7. 테스트 전략

| 층 | 무엇을 | 예 |
|---|---|---|
| 단위 (Vitest) | 규칙과 수치 | 점령 40초/27초, 수감 2회 후 사망, 3명 동시 수감 시 괴물 승리, 탈출구 2인 3초, 돌진 벽 정지, 캠핑 감속, 보호 4초 피격 무효, 시야 다각형 · 부채꼴 판정 |
| 봇 시나리오 | 서버 규칙 통합 | "유인": 괴물 봇이 러너 봇을 쫓는 동안 다른 봇이 거점 A 완료 / "구조": 두 명 수감 → 한 번에 해방 / "전체 판": 봇 4명으로 한 판 끝까지 |
| E2E (Playwright) | 브라우저 4개 동기화와 정보 차단 | 4 컨텍스트로 방 입장 → 시작 → 각자 이동 → 서로의 위치가 허용된 범위에서 일치 / 괴물 컨텍스트 스냅샷에 숨은 생존자 없음 / 역할별 스크린샷 저장 |
| 지연 | 100ms · 200ms | 내 캐릭터 입력 반응이 즉시인지(예측), 보정 튐이 작은지, 판정 결과가 네 클라이언트에서 같은지 |
| 성능 | 브라우저 4개 동시 | 각 탭 평균 FPS 55 이상 (헤드리스 측정치 기준) |
| 판정 불변 골든 (Vitest) | 그래픽 · 모바일 작업(M10~) 중 규칙 · 판정 · 정보 차단이 그대로인지 | 고정 시드 + 스크립트 입력(이동 · 조준 · 공격 · 돌진 · 포효 · 능력 · 구조 · 시야 전환) 960틱 → 60틱마다 게임 상태 해시 (`tests/unit/rules-golden.test.ts`). 바뀌면 GAME_DESIGN 변경 이력과 함께 갱신 |

E2E 스크린샷은 `artifacts/`에 저장하고, 사람이 볼 수 있게 마지막 보고에 경로를 적는다.

## 8. 실행과 배포

- `npm install` → `npm run dev` (서버 + 클라이언트 동시, 핫 리로드)
- `npm run build && npm start` → 포트 8080에서 서버가 클라이언트까지 서빙
- **같은 와이파이 플레이**: `npm start` 후 `http://<내 PC IP>:8080/?room=...`
- **인터넷 플레이**: Dockerfile로 서버를 배포한다. 한국 · 일본 리전을 쓴다(핑 30~60ms 목표). 서비스별 무료 플랜 조건은 바뀌므로 배포 시점에 확인한다. 무료 플랜이 잠드는 서비스라면 테스트 전에 한 번 접속해 깨운다
- 배포는 계정 인증이 필요하므로 Claude는 Dockerfile과 배포 안내(`docs/DEPLOY.md`)까지만 만들고, 실제 배포는 사람이 한다
- **그래픽 품질 높음 · 중간 · 낮음** (`?quality=high|medium|low` > 로비에서 고른 값 > 자동). 느린 PC는 로비의 그래픽 품질을 낮음으로(또는 주소에 `&quality=low`). 자동은 Canvas 렌더러 · 소프트웨어 WebGL이면 낮음, 하드웨어 WebGL PC는 높음(PC는 코어 수 · 메모리로 내리지 않는다). 판 중 FPS가 오래 낮으면 한 번 한 단계 내린다. `?scale`은 해상도 배율(0.25~1, 빈 값 · 0 · 음수 · 숫자 아님은 무시)이고 옛 `&scale=0.5` 링크도 "가볍게"로 계속 동작한다
