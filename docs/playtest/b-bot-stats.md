# 플레이테스트 반영 b — 봇끼리 판 전후 통계 (거점 세 곳 중 두 곳)

같은 도구(`scripts/bot-stats.ts`, b에서 꺼진 거점 · `required`를 알게 고친 판)로 같은 시드 300판(1~300, `room` 흐름 = 실제 방 + 실제 BotDriver)을 b 시작 커밋(`fef7430` = PR #33 병합 + 인수인계, git worktree를 `--repo`로)과 b 최종 코드(`32199fb`)에서 쟀다. 봇 두뇌는 b에서 거점 배정만 바꿨다: 세 곳 순서를 시드로 섞기 · 혼자 가는 역할도 셋 중 시드 · 괴물 번갈아 지키기 A → B → C · 끝났거나 꺼진 곳 빼기 · 목표 거점 이력(지금 목표가 안전하면 유지 — 검토에서 찾은 제자리 왕복 수리). 서성이기 · 반응 지연 · 괴물 연계는 c에서 한다.

```bash
npx tsx scripts/bot-stats.ts --matches 300 --seed 1 --repo <fef7430 worktree> --quiet --out before.json
npx tsx scripts/bot-stats.ts --matches 300 --seed 1 --quiet --out after.json
npx tsx scripts/bot-stats.ts --compare before.json after.json
```

읽는 법: '마지막 점령' = 탈출구를 켜는 데 한 곳만 더 필요하던 구간(거점 둘이면 남은 한 곳, 세 곳 중 두 곳이면 남은 두 곳 중 아무 데나). 같은 시드에서 판이 완전히 재현되지는 않는다(괴물 화면 임시 ID가 암호 난수 — `b-tests-meta.md` 7절) — 300판에서 판 몇 개가 달라 승패 ±1판 정도 흔들린다.

## 요약

- **괴물 승률 56.7% → 45.3%** (목표 30~40%보다 아직 조금 높다 — c에서 봇을 고친 뒤 다시 본다). 거점이 셋이 되어 '하나 끝낸 뒤 남은 한 곳만 지키기'가 덜 통한다: 마지막 점령을 못 끝낸 판 77/276(27.9%) → 46/261(17.6%), 마지막 점령 구간 평균 0:54 → 0:34, 탈출구가 켜진 판 199 → 215, 열린 판 131 → 164. 괴물 승 가운데 '사망 2명'이 115 → 79로 준다.
- **판 길이는 그대로 짧다**(중앙값 2:22 → 2:10, 7~10분인 판 0). 판 길이는 괴물 봇의 타격 속도가 정한다(명중률 83%, `c-bot-stats-baseline.md` 4.2절) — c에서 봇을 고친 뒤 다시 잰다.
- 거점 C가 가장 많이 끝났다(A 168 · B 119 · C 189판). 생존자 시작(감옥)에서 가깝고 괴물 시작(남동쪽)에서 멀다. B가 가장 적다(괴물 시작 2.6초 거리). 끝난 조합이 AB에 묶이지 않는다.
- 생존자 봇이 쫓기지 않는데 서 있던 시간 14.0초 → 5.9초. 중간 측정(목표 거점 이력 전, `c209db5`)은 괴물 승률 41.0% · 6.0초였는데, 그때는 목표 거점이 내 자리에 따라 깜빡여 제자리 왕복이 많았다(시드 1~40에서 목표가 바뀐 횟수 / 1초 안에 되돌아옴: b 전 3073 / 2298 → 이력 전 7171 / 5711 → 최종 968 / 68).
