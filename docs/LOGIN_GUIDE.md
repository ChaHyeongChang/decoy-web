# 구글 로그인 켜기 안내 — 태블릿으로 따라 하기

선택형 구글 로그인(로그인하면 레벨 · 불씨 · 도전 · 의상 기록을 PC · 휴대폰 · 스토어 앱에서 같이 쓴다)을 **켜기 위해 사람이 직접 해야 하는 일**을 순서대로 적은 문서다. 구글 클라우드 · Neon(DB) · Render 계정과 비밀값이 필요한 일이라 Claude가 대신할 수 없다. 설계는 `docs/ACCOUNT_PLAN.md`, 결정과 이유는 `docs/DECISIONS.md` 15절, Play 신고 값은 `docs/STORE_LISTING.md` 4장.

- 로그인 기능은 **기본 꺼짐**이다. 꺼져 있으면 게임은 지금과 똑같다(게스트 · 이 기기 기록, 설정에 '계정' 칸 없음)
- **순서가 중요하다**: 구글 클라우드(1~3) → DB(Neon, 4) → Render 환경 변수(5) → **Play 신고 고치기(6)** → 그다음에 켠다(7). 신고를 고치기 전에 켜면 스토어 앱의 데이터 보안 신고가 실제와 달라진다
- 우리 서버에 오는 것은 **구글 고유 ID뿐**이다. 요청 범위가 `openid`라 이메일 · 이름 · 사진은 받지 않는다. 구글 스크립트 · 팝업 없이 페이지째 구글 로그인 화면으로 갔다가 돌아온다

> 정책 · 화면 이름은 **2026년 10월 기준**이다. 구글 클라우드 · Neon · Render 화면은 자주 바뀌므로 버튼 이름이 다르면 비슷한 이름을 누른다. 이 문서를 쓴 작업 환경에서는 구글 · Neon · Render 문서 사이트를 열 수 없어 화면 이름 몇 곳을 직접 확인하지 못했다(그 자리에 '확인 못 함'이라 적었다) — 화면 안내가 이 문서와 다르면 **화면 안내를 따른다.**

> **⚠ 비밀값은 저장소(GitHub) · 메신저 · 이메일에 두지 않는다.** `DECOY_SESSION_SECRET` · `DATABASE_URL`(DB 비밀번호가 들어 있다)은 Render 대시보드 **Environment**에만 넣는다. 구글 클라우드가 보여 주는 **클라이언트 보안 비밀번호(client secret)는 쓰지 않는다** — 우리 방식에는 필요 없으니 어디에도 넣지 않고, 내려받기 JSON도 저장소 폴더에 두지 않는다.

**준비물**

- 구글 계정 하나(구글 클라우드에 로그인할 것. Play 개발자 계정과 같은 계정이면 관리하기 쉽다)
- Render 대시보드 로그인(GitHub)
- Neon 가입에 쓸 구글 · GitHub 계정 또는 이메일(4단계, 무료 플랜)
- 앱 주소 `<서비스 주소>`: Render 대시보드 위쪽의 `https://decoy-web-xxxx.onrender.com`. 내 도메인을 연결했다면 그 주소도
- 공개해도 되는 이메일(구글 로그인 화면의 '지원 이메일'로 보일 수 있다 — 처리방침 문의처 `PRIVACY_CONTACT`와 같은 주소 권장)
- 태블릿 브라우저(사파리 · 크롬). 구글 클라우드 콘솔은 PC용 화면이라 메뉴가 잘려 보이면 **데스크톱 웹사이트 요청**을 켠다(사파리: 주소창 왼쪽 `가가` 버튼, 크롬: `⋮` 메뉴)

## 1. 구글 클라우드 프로젝트 만들기 (5분)

1. 태블릿 브라우저에서 `https://console.cloud.google.com` 을 열고 구글 계정으로 로그인한다. 처음이면 서비스 약관에 동의한다
2. 위쪽의 프로젝트 고르기(프로젝트 이름 또는 "프로젝트 선택") → **새 프로젝트**
3. 프로젝트 이름: `decoy` (아무 이름이나 된다 — 사용자에게 보이지 않는다). 조직 · 위치는 "조직 없음" 그대로 → **만들기**
4. 다 만들어지면 위쪽에 그 프로젝트가 골라져 있는지 확인한다(다른 프로젝트에 만들지 않게)

- 구글 로그인만 쓰므로 결제 계정은 넣지 않아도 된다. 결제를 등록하라는 안내가 떠도 로그인에는 필요 없다

## 2. Google Auth Platform — 앱 정보 · 대상 · 게시 (15분)

예전 이름은 **OAuth 동의 화면**이다. 왼쪽 메뉴(☰) → **API 및 서비스 › OAuth 동의 화면**(또는 **Google Auth Platform**)으로 간다. 처음이면 **시작하기**를 누른다.

1. **앱 정보**
   - 앱 이름: `DECOY` (구글 로그인 화면에 보일 수 있는 이름)
   - 사용자 지원 이메일: 준비물의 공개 이메일
2. **대상**: **외부**(External) — 누구나 자기 구글 계정으로 로그인한다. '내부'는 회사 Google Workspace 전용이라 고르지 않는다
3. **연락처 정보**: 개발자 연락처 이메일(구글이 이 프로젝트 일로 연락하는 곳, 공개되지 않는다)
4. 사용자 데이터 정책 동의에 체크 → **만들기**
5. **브랜딩**(Branding) 화면에서 더 적는다
   - **앱 로고: 올리지 않는다.** 로고를 올리면 구글의 브랜드 확인(심사)을 받아야 한다
   - 앱 도메인(선택): 애플리케이션 홈페이지 `https://<서비스 주소>/`, 개인정보처리방침 `https://<서비스 주소>/privacy`. 서비스 약관은 비워 둔다
   - **승인된 도메인**: 아래 '공용 접미사 도메인 주의'를 보고 넣는다
   - 개발자 연락처 이메일이 비었으면 3번과 같은 주소 → **저장**
6. **데이터 액세스**(Data Access, 범위): **아무 범위도 추가하지 않는다.** 서버가 로그인 때 요청하는 범위는 `openid` 하나다(로그인 확인용 기본 범위). 이메일 · 프로필 범위를 넣지 않는다 — 처리방침 · Play 신고는 '이메일 · 이름 · 사진을 받지 않는다'로 적혀 있다
7. **대상**(Audience) 화면에서 **게시 상태**를 본다
   - **테스트**(Testing)이면 **앱 게시**(Publish app) → 확인 → **프로덕션**(In production)이 되어야 한다
   - 테스트 상태로 두면 같은 화면의 **테스트 사용자**에 넣은 구글 계정만 로그인되고, 나머지 사람은 구글 화면에서 "액세스 차단됨" 같은 오류를 본다
   - `openid`만 쓰는 앱은 민감한 범위가 없어 게시에 구글 심사가 필요 없는 것으로 안다(확인 못 함 — 화면이 확인 · 심사를 요구하면 안내를 따른다)

**공용 접미사 도메인 주의 (`onrender.com`)**

- 승인된 도메인에는 '최상위 비공개 도메인'을 넣는다. `onrender.com`처럼 여러 사람이 나눠 쓰는 공용 접미사 도메인은 `onrender.com` 자체가 아니라 **내 서비스 주소 전체**(`decoy-web-xxxx.onrender.com`)가 그 자리다 — 이것을 넣는다
- 3단계에서 리디렉션 URI를 저장하면 그 도메인이 저절로 더해질 수도 있다. 목록에 이미 있으면 그대로 둔다
- 내 도메인을 연결했다면 그 도메인(예: `example.com`)도 넣는다
- 이 작업 환경에서 구글 문서 · 공용 접미사 목록을 열지 못해 위 내용을 직접 확인하지 못했다. 화면이 받지 않거나 다르게 안내하면 **화면 안내를 따른다**

## 3. OAuth 클라이언트 ID 만들기 (10분)

1. Google Auth Platform › **클라이언트**(Clients) → **클라이언트 만들기**(또는 API 및 서비스 › 사용자 인증 정보 › **사용자 인증 정보 만들기 › OAuth 클라이언트 ID**)
2. 애플리케이션 유형: **웹 애플리케이션**
3. 이름: `DECOY web` (사용자에게 보이지 않는다)
4. **승인된 자바스크립트 원본: 비워 둔다.** 우리 방식은 페이지째 이동하는 리디렉트라 필요 없다
5. **승인된 리디렉션 URI** → **URI 추가** → `https://<서비스 주소>/auth/google/callback`
   - `https`로 시작하고 끝에 `/`를 붙이지 않는다. 글자 하나라도 다르면 구글이 `redirect_uri_mismatch`로 막는다
   - 내 도메인을 연결했다면 그 주소도 하나 더: `https://<내 도메인>/auth/google/callback` (사람들이 여는 주소마다 하나씩)
   - 로컬 개발 주소는 넣지 않는다(자동 시험은 가짜 구글을 쓴다)
6. **만들기** → 창에 나오는 **클라이언트 ID**(`…apps.googleusercontent.com`으로 끝난다)를 복사해 둔다(5단계에서 쓴다). 클라이언트 보안 비밀번호는 쓰지 않는다
7. 저장한 뒤 구글 쪽에 반영되기까지 몇 분 걸릴 수 있다

로그인 시작 주소는 `https://<서비스 주소>/auth/google/start`(게임의 로그인 단추가 연다)이고, 구글이 로그인 결과를 위 리디렉션 URI로 보낸다. 시작 주소는 구글 클라우드에 넣지 않는다.

## 4. DB 가입 — Neon (계정 기록 저장소, 10분)

계정 기록(구글 고유 ID + 성장 기록 글)은 **Neon**의 PostgreSQL에 둔다. **무료 플랜**, 지역은 **AWS Asia Pacific 1 (Singapore)**(지역 ID `aws-ap-southeast-1` — Render 서버도 싱가포르라 가깝다). 고른 이유는 `docs/DECISIONS.md` 15절. Neon 화면은 영어이고, 이 작업 환경에서 neon.com을 열 수 없어 버튼 이름은 직접 확인하지 못했다(확인 못 함) — 다르면 비슷한 이름을 누른다.

1. 태블릿 브라우저에서 `https://neon.com` → **Sign up** → 구글 · GitHub · 이메일 중 하나로 가입한다(구글 클라우드와 같은 구글 계정이면 관리하기 쉽다). 요금제를 고르라고 하면 무료(**Free**)
2. 첫 화면(또는 **New Project**)에서 프로젝트를 만든다
   - 프로젝트 이름(Project name): `decoy` (아무 이름이나 된다 — 사용자에게 보이지 않는다)
   - Postgres 버전: **기본값 그대로**
   - 클라우드(Cloud provider): AWS (기본값)
   - **지역(Region): AWS Asia Pacific 1 (Singapore)** — ⚠ 프로젝트를 만든 뒤에는 지역을 바꿀 수 없다(바꾸려면 새 프로젝트를 만들어 기록을 옮긴다 — 11절). 처리방침 7번(국외 이전)도 싱가포르로 적혀 있다
   - 그 밖의 선택은 기본값 그대로 → **Create project**(만들기)
3. 프로젝트 대시보드의 **Connect**(연결) 단추 → 연결 창
   - 데이터베이스(`neondb`) · 역할(role)은 기본값 그대로
   - **접속 문자열**(Connection string) 모양을 고른다 — `postgresql://`로 시작하는 한 줄. 앞에 `psql '`가 붙은 명령 모양이 아니다
   - 비밀번호가 `****`로 가려져 있으면 **Show password**(비밀번호 보이기) 같은 단추를 먼저 누른 뒤 **복사**(Copy). 가려진 채 복사하면 켤 때 `28P01` 오류가 난다(10단계)
   - 연결 풀링(Connection pooling)은 켜짐 · 꺼짐 어느 쪽이든 된다(주소의 호스트에 `-pooler`가 붙느냐만 다르다 — 서버는 둘 다 쓸 수 있다)
4. 복사한 값은 이렇게 생겼다: `postgresql://사용자:비밀번호@ep-…-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
   - 호스트에 `ap-southeast-1`이 보이면 싱가포르다
   - 고치지 않고 **그대로** 쓴다. 끝의 `?sslmode=require…`도 지우지 않는다(서버가 DB 연결을 암호화하고 인증서를 확인한다)
   - **이 값에는 DB 비밀번호가 들어 있다.** 메모장 · 메신저 · 저장소에 남기지 말고 바로 5단계 Render에 붙인다. 잃어버리면 Connect 창에서 다시 복사하면 된다
5. **표(table)는 만들지 않는다.** 로그인을 켠 서버가 처음 뜰 때 `decoy_accounts` 표를 스스로 만든다(8단계에서 확인)

**Neon 무료 플랜에서 알아 둘 것** (아래 무료 조건은 2026-10에 검색으로 본 Neon 문서 · 요금 페이지의 값이다 — 이 작업 환경에서 Neon 콘솔 화면 · 버튼 이름은 직접 보지 못했다. 바뀔 수 있으니 켜기 전에 `https://neon.com/pricing`에서 다시 본다 — 다르면 개발자에게 알린다)

| 항목 | 무료 플랜 | 게임에서는 |
|---|---|---|
| 잠들기 | 5분 동안 쓰지 않으면 compute(DB를 돌리는 컴퓨터)가 잠든다. 무료는 끌 수 없다 | 잠든 뒤 첫 계정 요청(로그인 · 상태 읽기 · 판 적립)이 깨우느라 보통 1초 안팎, 드물게 몇 초 늦다. 서버는 기다리고 연결 오류면 한 번 더 시도한다(시도 하나 4.5초 — 그중 접속 4초, 한 번 더까지 합쳐 9초 안. 화면은 12초까지 기다린다). 단 **친구 방 링크 · 마지막 방 복귀로 연 경우는 계정 상태를 3초까지만** 기다린다 — 그보다 늦게 깨면 그 판은 게스트로 하고 이 기기 기록에 쌓인다(계정에는 쌓이지 않는다) |
| compute 시간 | 프로젝트당 한 달 100 CU-시간 | 넘으면 그달 남은 동안 compute가 멈춘다 → 계정 요청이 모두 실패(503)해 로그인한 사람도 게스트(이 기기 기록)로 하고 판은 끝까지 그대로. 다음 달 초에 풀린다(또는 11절 유료). 한 달에 한 번 사용량을 본다(`docs/HUMAN_CHECKS.md`) |
| 저장 용량 | 프로젝트당 0.5GB | 계정 하나는 행 하나(구글 고유 ID · 성장 기록 글)라 작아 넘을 일은 드물다. 넘으면 읽기(로그인 · 계정 기록 보기)는 되지만 **쓰기가 실패한다**(판 적립 · 접속 보상 · 의상 — '저장하지 못했어요', 첫 로그인의 기록 올리기, 처음 로그인하는 구글 계정의 계정 만들기). compute와 달리 **다음 달에 풀리지 않는다** — 행을 지우거나 유료로 올릴 때까지 |
| 복원(PITR) 기간 | 6시간 (최대 1GB-월) | 지운 계정 기록이 Neon의 복원용 기록에 **최대 6시간** 남았다가 자동으로 지워진다 — 처리방침 3 · 7 · 8번 · 계정 삭제 페이지(`ACCOUNT_BACKUP_RETENTION`)에 적었다. 그보다 오래된 시점으로는 되돌릴 수 없다(되돌리기는 원칙적으로 하지 않는다 — 10단계 표 마지막 줄) |
| 회사 · 위치 | Neon, LLC (Databricks 계열, 미국) · 저장은 싱가포르 | 처리방침 6번(위탁) · 7번(국외 이전). Neon의 개인정보 문의처는 neon.com의 Privacy Policy에 적힌 연락처(법인 이름 · 연락처가 처리방침과 같은지 켜기 전에 본다 — `docs/HUMAN_CHECKS.md`) |

## 5. Render 환경 변수 넣기 (10분, 재배포)

Render 대시보드 → 서비스 `decoy-web` → **Environment** → **Add Environment Variable**(또는 **Edit**). **저장하면 서버가 다시 배포되어 열려 있던 방이 사라진다** — 아무도 없을 때 한다.

| 키 | 넣을 값 | 비고 |
|---|---|---|
| `GOOGLE_CLIENT_ID` | 3단계의 클라이언트 ID | 비밀값은 아니지만 저장소에 적지 않고 여기에만 넣는다 |
| `DECOY_SESSION_SECRET` | **넣지 않는다 — 있는지 확인만** | 저장소의 `render.yaml`(`generateValue: true`)이 무작위 값을 저절로 만든다. 목록에 없으면 아래처럼 직접 만든다 |
| `DATABASE_URL` | 4단계에서 복사한 Neon 접속 문자열 **그대로**(`postgresql://`로 시작하는 한 줄, 따옴표 · 앞뒤 빈칸 없이) | **비밀값**(DB 비밀번호가 들어 있다) — 여기에만 넣는다. 저장소의 `render.yaml`에는 키만 있고 값은 없다(`sync: false`). `DECOY_LOGIN`이 없거나 `0`인 동안은 넣어 두어도 서버가 DB에 접속하지 않는다 |
| `DECOY_ACCOUNT_TIMEZONE` | **넣지 않는다** (기본 `Asia/Seoul`) | 계정의 하루(일일 도전 · 접속 보상)가 바뀌는 시간대. 바꿀 일이 있을 때만(예: `Asia/Tokyo`) |
| `DECOY_LOGIN` | **아직 넣지 않는다** | 7단계(Play 신고를 고친 뒤)에 넣는다 |

- 키가 목록에 이미 있으면 그 값 칸에, 없으면 **Add Environment Variable**로 더한다. 키 이름은 글자까지 같아야 한다(`DATABASE_URL`)
- `DECOY_SESSION_SECRET`이 목록에 없을 때: 값 칸 옆에 **Generate**(무작위 값 만들기) 단추가 있으면 그것을 쓴다(확인 못 함). 없으면 비밀번호 관리자의 '비밀번호 생성'으로 **32자 이상** 무작위 글자(영문 대소문자 · 숫자)를 만들어 넣는다. PC가 있으면 `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`로 만든 값도 된다. 값은 어디에도 따로 적어 두지 않아도 된다(잃어버리면 새로 만들면 되고, 그때 모두 한 번 로그아웃될 뿐 계정 기록은 그대로다)
- 한 번 정한 `DECOY_SESSION_SECRET`은 바꾸지 않는다. 바꾸면 로그인한 모든 사람이 로그아웃된다(다시 로그인하면 기록은 그대로)
- 확인: 저장 → 다시 배포가 끝나면(**Logs**에 `DECOY 서버 시작`) 브라우저로 `https://<서비스 주소>/api/account`를 연다 → `{"on":false}`(아직 꺼짐 — 정상)

## 7. 기능 켜기 (5분, 재배포)

1. Render → 서비스 `decoy-web` → **Environment** → **Add Environment Variable**: 키 `DECOY_LOGIN`, 값 `1` → **Save Changes** (다시 배포된다 — 아무도 없을 때)
2. 배포가 끝나면 **Logs**를 본다
   - `계정 로그인: 켜짐 (postgres)` → 켜졌다. 8단계로
   - `계정 로그인: 꺼짐 (…)` → 필요한 값이 하나라도 빠졌거나 틀려 서버가 **꺼진 채로** 떴다. 괄호 안에 그 값의 **이름만** 적힌다(값은 적지 않는다. 예: `DATABASE_URL 없음` · `DATABASE_URL 틀림`) → 5단계로 돌아가 그 이름을 고친다(10단계 표)
   - 켜짐 뒤에 `계정 저장소 시작 실패 (계정 요청은 503, 판은 그대로)`나 `계정 DB 오류 …`가 보이면 DB에 닿지 않는 것이다 → 10단계 표에서 그 줄의 오류 코드를 찾는다
   - **`계정 DB 연결: …`으로 시작하는 줄이 없어야 한다**(`인증서를 확인하지 않음` · `암호화하지 않음`). 있으면 `DATABASE_URL`에서 끝의 `?sslmode=require`가 빠졌거나 바뀐 것이다 — 그대로 두면 처리방침 10번('DB 연결은 암호화(TLS)하고 인증서를 확인')이 사실과 달라진다. 바로 `DECOY_LOGIN`을 `0`으로 되돌리고, 4단계 3의 Connect 창에서 접속 문자열을 **고치지 않고** 다시 복사해 넣은 뒤 다시 켠다

## 8. 확인 (30분)

1. 로그인하지 않은 브라우저로 `https://<서비스 주소>/api/account`를 연다 → `{"on":true,"signedIn":false}`. `{"on":false}`면 7단계 2의 로그를 본다
2. **PC 크롬**: 첫 화면 → 설정 → **계정** → **Google 계정으로 로그인** → 구글 화면에서 계정 고르기 → 게임으로 돌아와 로그인됐다는 안내가 뜬다. 이 기기에 기록이 있으면 '이 기기 기록을 계정에 올렸다'는 안내(계정이 비었을 때) 또는 '계정 기록 · 이 기기 기록' 고르기 창(둘 다 있을 때)
3. 온라인 판(빠른 매칭 또는 친구 방) 한 판 → 결과에 계정에 저장했다는 한 줄. 봇과 연습은 계정에 적립하지 않는다(결과에 한 줄 안내 — 정상)
4. **휴대폰 크롬**(다른 기기): 같은 구글 계정으로 로그인 → 레벨 · 불씨 · 의상이 PC와 같다
5. **스토어 앱**(설치한 앱): 설정 → 계정 → 로그인 → 구글 화면이 열렸다가(위에 주소 줄이 잠깐 보일 수 있다) 게임으로 돌아온다. `403 disallowed_useragent`가 뜨면 아래 문제 해결
6. **로그아웃**: 설정 → 계정 → 로그아웃 → 이 기기 기록(게스트)으로 돌아온다
7. **계정 삭제**(시험용 구글 계정으로): 설정 → 계정 → 계정 삭제(두 번 확인), 그리고 게임에서 한 번 로그인해 둔 다른 시험 계정으로 웹 페이지 `https://<서비스 주소>/account/delete` → 로그인해 삭제 → 지웠다는 안내(게임에서 로그인한 적 없는 구글 계정이면 "이 Google 계정으로 만든 DECOY 계정이 없습니다" — 계정을 만들지 않는다). 삭제 페이지의 로그인은 게임을 로그인 상태로 만들지 않는다. 지운 뒤 같은 구글 계정으로 다시 로그인하면 새 계정으로 시작한다(그 기기에 게스트 기록이 있으면 새 계정에 올린다)
8. Render **Logs**: 로그인 · 적립 횟수와 실패 종류만 보이고 구글 고유 ID · 계정 ID · 토큰 · DB 주소가 찍히지 않는지
9. **Neon 콘솔** → 프로젝트 `decoy` → **Tables**(또는 **SQL Editor**에서 `SELECT count(*) FROM decoy_accounts;` → **Run**): 서버가 만든 `decoy_accounts` 표가 있고, 위에서 로그인한 계정 수만큼 행이 있는지(지운 계정은 없다). 칸은 `id` · `sub` · `profile` · `created` · `updated` · `rev`(기록을 바꾼 횟수)뿐이다 — 이메일 · 이름 칸이 없다
10. 남은 실기기 확인은 `docs/HUMAN_CHECKS.md` '선택형 구글 로그인'

- 5분 넘게 아무도 계정을 쓰지 않은 뒤의 첫 로그인 · 상태 읽기는 Neon이 깨느라 몇 초 늦을 수 있다(정상, 4단계 표)
- 친구 방 링크(방 주소) · 마지막 방 복귀로 앱을 열면 계정 상태를 **3초까지만** 기다리고 방에 들어간다. Neon이 그보다 늦게 깨면 그 판은 게스트로 하고 이 기기 기록에 쌓인다(계정에는 쌓이지 않는다 — 정상, 판은 그대로). 그 밖의 계정 요청(상태 읽기 · 설정 › 계정 · 판 적립)은 12초까지 기다린다(첫 화면의 레벨 칩은 3초가 지나면 이 기기 기록을 보이다가 계정을 읽으면 계정 기록으로 바뀐다)

## 9. 끄기

1. Render → **Environment**에서 `DECOY_LOGIN` 값을 `0`으로 바꾼다(키를 지워도 같다 — `1`이 아니면 꺼짐) → **Save Changes** (다시 배포). Logs에 `계정 로그인: 꺼짐 (DECOY_LOGIN)`
2. 끄면 설정의 '계정' 칸이 사라지고, 로그인했던 사람도 **게스트(이 기기 기록)로** 돌아간다. **계정 기록은 DB에 남는다** — 다시 켜면 그대로 이어진다. 꺼진 동안 한 온라인 판은 이 기기 기록에만 쌓인다(서버는 화면이 계정을 밝힐 때만 계정에 적립한다 — 다시 켜도 그 판이 계정에 몰래 들어가지 않는다)
   - 로그인했던 기기는 이 기기 표시(`decoy:account`)를 **지우지 않고 남긴다**(다시 켜면 묻지 않고 같은 계정으로). '지금은 로그인을 쓸 수 없어요' 안내는 **처음 한 번만** 뜨고, 그 뒤로는 안내 없이 **앱을 열 때마다 계정 상태를 한 번 읽어** 다시 켜졌는지만 본다(`GET /api/account` → `{on:false}`, 요청 하나 · 판은 그대로). 처리방침의 `decoy:account` 기간에 '로그인 기능이 꺼진 동안은 남음'이라고 적어 두었다
3. 꺼진 동안에는 앱 안 계정 삭제를 쓸 수 없고, 계정 삭제 웹 페이지도 계정을 지우지 못한다. 그러니 **잠깐이 아니라 오래 끌 때는** DB의 계정 기록을 지우고, Play 신고를 로그인 꺼짐 값(STORE_LISTING 1~3장)으로 되돌린다. 오래 꺼 두어도 로그인했던 기기는 표시가 남아 앱을 열 때마다 상태 요청 하나를 보낸다(위 2 — 안내는 뜨지 않는다). 다시 켜지 않을 것이 확실하면 그 요청도 '로그인 꺼짐' 응답 하나라 그대로 두어도 되고, 사이트 데이터를 지우면 사라진다
4. 운영을 그만둘 때도 같다(`docs/PLAY_STORE_GUIDE.md` 13단계)

**꺼진 동안 계정 삭제 요청이 오면** (문의처로 "예전에 로그인했는데 지워 달라")

꺼져 있으면 계정 삭제 페이지는 "문의처로 알려 달라"고 안내한다. 서버는 이메일을 저장하지 않아 요청한 사람의 계정을 따로 찾을 수 없으므로 둘 중 하나로 처리한다.

- (가) **잠깐 켜고 직접 지우게 하기** — Play 신고가 아직 '로그인을 켤 때' 값일 때(잠깐 끈 경우)만: 7단계처럼 `DECOY_LOGIN=1`로 켠다 → 요청자에게 `https://<서비스 주소>/account/delete`에서 그 구글 계정으로 로그인한 뒤 「계정과 기록 삭제」를 누르라고 알린다(언제 다시 끄는지 함께) → 요청자가 지웠다고 알려 오거나 알린 때가 지나면 다시 끈다(위 1)
- (나) **DB의 계정 기록 전체 지우기** — 오래 끈 경우(위 3) · 운영을 그만둘 때: 아래 방법(Neon SQL Editor)으로 계정 기록 전체를 지운다
- 처리한 뒤 요청자에게 답장한다: (가)는 다시 껐다는 것(지우지 못했으면 (나)로), (나)는 서버의 계정 기록 전체를 지웠다는 것

**DB의 계정 기록 전체 지우기** (위 3 · (나)에서 쓴다)

1. `https://console.neon.tech`(또는 neon.com → 로그인) → 프로젝트 `decoy` → 왼쪽 메뉴 **SQL Editor**
2. 아래 한 줄을 넣고 **Run**(실행):

   ```sql
   DELETE FROM decoy_accounts;
   ```

3. 확인: `SELECT count(*) FROM decoy_accounts;` → **Run** → `0`
4. **표는 남겨 둔다**(`DROP TABLE`은 하지 않는다). 다시 켜면 서버가 그 빈 표를 그대로 쓴다. 지운 행은 Neon의 복원용 기록에 최대 6시간 남았다가 자동으로 사라진다(처리방침 3 · 7 · 8번)

- **특정 사람의 계정만 골라 지울 수는 없다.** DB에는 구글 고유 ID와 성장 기록 글만 있고 이메일 · 이름이 없어, 요청한 사람의 행이 어느 것인지 알 수 없다(위 (가)는 본인이 직접 로그인해 지우는 길이다)
- 운영을 그만둘 때는 기록을 지운 뒤 Neon 프로젝트를 통째로 지워도 된다(프로젝트 **Settings** → **Delete project**). 지운 프로젝트를 Neon이 며칠 동안 되살릴 수 있게 남겨 둘 수 있다 — 지울 때 화면 안내(되살리기 기간)를 읽고, 그 기간이 지나야 지운 데이터가 완전히 사라진다고 본다(확인 못 함). 다시 켤 일이 있으면 4단계부터 새로 한다

## 10. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 구글 화면에 `400 redirect_uri_mismatch` | 3단계 리디렉션 URI가 지금 연 주소와 글자까지 같은지(`https` · 도메인 · `/auth/google/callback`, 끝에 `/` 없음). 내 도메인으로 열었다면 그 주소도 넣었는지. 저장 뒤 몇 분 기다린다 |
| 구글 화면에 `403 disallowed_useragent` | 구글은 앱 안 웹뷰(WebView)의 로그인을 막는다. 스토어 앱이면 PWABuilder의 **Fallback behavior**가 **Custom Tabs**인지(`docs/PLAY_STORE_GUIDE.md` 5단계) — WebView로 만든 패키지는 다시 만든다. 메신저(카카오톡 등) 안에서 링크를 열었다면 크롬 · 사파리로 다시 연다 |
| 구글 화면에 "액세스 차단됨" · 테스트 사용자만 로그인된다 | 2단계 7: 게시 상태가 **테스트**다 → **앱 게시**로 프로덕션 |
| 로그인 뒤 주소가 `/?login=cancel` | 구글 화면에서 취소했다 — 정상 |
| 로그인 뒤 주소가 `/?login=fail` | 로그인 확인에 실패했다(구글 화면에 10분 넘게 머묾 · 다른 탭에서 로그인을 다시 시작 · 시계가 크게 틀림 등). 다시 로그인한다. 계속되면 Render Logs의 실패 종류와 `GOOGLE_CLIENT_ID`가 3단계 값과 같은지 본다 |
| 로그인 뒤 주소가 `/?login=off` · `/api/account`가 `{"on":false}` | `DECOY_LOGIN`이 `1`이 아니거나(없음 · `0`) 필요한 값이 빠졌다 → Logs의 빠진 이름(7단계) |
| 로그인 뒤 주소가 `/?login=db` · 계정을 읽지 못했다는 안내 | 계정 기록 저장소(Neon)에 닿지 않는다. 게임은 게스트로 그대로 된다. Logs의 `계정 DB 오류 …` 줄을 아래 표에서 찾는다 |
| 다른 기기에서 레벨이 다르다 | 같은 구글 계정인지, 첫 로그인 고르기 창에서 어느 기록을 골랐는지 |
| 모두 갑자기 로그아웃됐다 | `DECOY_SESSION_SECRET`이 바뀌었다(지웠다 다시 만들었거나 새로 생김). 다시 로그인하면 기록은 그대로다 |
| 아이폰 홈 화면에 추가한 앱에서 로그인 뒤 게임으로 돌아오지 않는다 | 사파리에서 로그인해 본다. 결과를 `docs/HUMAN_CHECKS.md` '선택형 구글 로그인'에 적는다 |

**DB(Neon) 문제** — 서버 로그에는 오류 코드와 짧은 힌트만 적힌다(DB 주소 · 비밀번호 · 호스트는 적지 않는다, 같은 코드는 1분에 한 번). 서버는 DB 시도 하나를 4.5초(그중 접속 4초)에서 끊는다. 끝에 `(한 번 더 시도)`가 붙은 줄은 서버가 연결 오류를 보고 0.3초 뒤 다시 해 본 것이다 — 요청 하나에 쓰는 9초 가운데 1초 넘게 남았을 때만 하고, 두 번째 시도는 남은 시간만 쓴다(첫 시도가 4.5초를 다 썼으면 약 4.2초). 다시 해도 안 되면 그 표시가 없는 줄이 하나 더 찍힌다. 어느 경우든 **판은 그대로** 되고, 계정에 닿지 못한 접속은 게스트(이 기기 기록)로 한다.

| 증상 · 로그 | 원인 · 할 일 |
|---|---|
| `계정 로그인: 꺼짐 (DATABASE_URL 없음)` | Render **Environment**에 `DATABASE_URL`이 없거나 키 이름이 다르다 → 5단계 |
| `계정 로그인: 꺼짐 (DATABASE_URL 틀림)` | 값의 모양이 틀렸다: `postgresql://`로 시작하는지, 앞뒤에 따옴표 · 빈칸 · `psql` 같은 글자가 붙지 않았는지, 중간이 잘리지 않았는지 → 4단계 3의 Connect 창에서 접속 문자열을 다시 복사해 붙인다. 호스트가 `[::1]` 같은 IPv6 숫자 주소이거나 호스트가 여러 개면 받지 않는다(Neon 주소는 해당 없음) |
| `계정 저장소를 만들지 못함 (DATABASE_URL 확인)` 뒤 `계정 로그인: 꺼짐 (DATABASE_URL 틀림)` | 모양은 맞지만 서버가 DB 연결을 준비하지 못했다 — 주소의 `sslrootcert=`가 가리키는 인증서 파일을 읽지 못하는 경우 등. Neon 주소에는 `sslrootcert`가 없으니 Connect 창에서 다시 복사한다. 다른 DB로 옮기며 넣었다면 11절 ④. 서버와 판은 그대로 뜬다(로그인만 꺼짐) |
| `계정 DB 연결: 인증서를 확인하지 않음 (DATABASE_URL에 sslmode=require가 없다 — 처리방침 10번 확인)` · `계정 DB 연결: 암호화하지 않음 (DATABASE_URL이 sslmode=disable — 처리방침 10번 확인)` | 서버가 켤 때 찍는 경고다. Neon 주소를 그대로 붙였다면 나오지 않는다 — `?sslmode=require`가 지워졌거나 바뀌었다 → Connect 창에서 다시 복사한다(7단계 2). 11절 ④에서 Render 내부 주소를 일부러 쓴 경우에만 나오는 것이 맞고, 그때는 처리방침 10번을 맞춘다(11절 ⑥) |
| `계정 저장소 시작 실패 (계정 요청은 503, 판은 그대로)` | 서버가 켤 때 DB에 닿지 못했다. 바로 근처의 `계정 DB 오류` 줄로 원인을 본다. 서버는 계정 요청이 올 때 30초에 한 번 다시 시도하므로, DB가 돌아오면 다시 배포하지 않아도 된다 |
| `계정 DB 오류 28P01 — DB 사용자 · 비밀번호가 틀림 (DATABASE_URL 확인)` (또는 `28000`) | 비밀번호가 `****`로 가려진 채 복사됐거나, Neon에서 비밀번호를 새로 만들었다(Reset password) → Connect 창에서 **비밀번호가 보이게 한 뒤** 다시 복사해 `DATABASE_URL`을 바꾼다 |
| `계정 DB 오류 3D000 — DB 이름이 틀림` | 주소의 `/neondb` 부분이 다르다 → 접속 문자열을 고치지 말고 다시 복사한다 |
| `계정 DB 오류 ENOTFOUND — DB 주소(호스트)를 찾을 수 없음` | 호스트(`ep-…neon.tech`)가 잘렸거나 Neon 프로젝트를 지웠다 → Neon 콘솔에 프로젝트가 있는지 보고 다시 복사한다 |
| `계정 DB 오류 CONNECT_TIMEOUT — DB가 깨는 중이거나 닿지 않음` | 가끔 한 줄이면 **정상**이다(잠든 compute가 깨는 중 — 서버가 한 번 더 시도한다). 몇 분 동안 계속되면 Neon 콘솔에서 프로젝트 · compute 상태와 Neon 장애 공지를 본다 |
| `계정 DB 오류 QUERY_TIMEOUT — DB 응답 없음 (연결을 새로 만든다)` | 시도 하나(접속 + 질의)가 4.5초 안에 끝나지 않아 서버가 그 연결 묶음을 버리고(그 소켓도 바로 닫는다) 새로 만들었다(멈춘 연결에 요청이 매달리지 않게). 그때 함께 끊긴 다른 요청은 새 묶음으로 다시 한다. 가끔 한 줄이면 괜찮다. 계속되면 위 `CONNECT_TIMEOUT`과 같이 본다 |
| `계정 DB 오류 CONNECT_TIMEOUT — 응답이 없어 15초 동안 DB를 쉰다 (계정 요청은 503, 판은 그대로)` (코드는 `QUERY_TIMEOUT`일 수도) | 요청 하나의 시도가 모두(한 번 더 포함) 시간을 넘겼다. 서버는 그동안 DB에 접속하지 않고 계정 요청을 바로 503으로 돌려준다(로그 없이 — 화면은 게스트). 쉬는 시간은 이어질 때마다 15초 → 30초 → 1분 … 최대 5분으로 늘고(여러 요청이 한꺼번에 실패해도 한 번만 센다), DB 요청이 한 번이라도 되면 바로 풀리고 처음(15초)으로 돌아간다. 한 번이면 깨는 중이 길었던 것이다. 몇 분 넘게 이어지면 Neon 콘솔에서 compute 상태 · 장애 공지 · 아래 한도 초과를 본다 |
| `계정 DB 오류 RECONNECT_LOOP — DB가 오류 없이 연결을 거듭 끊음 (DATABASE_URL · DB 상태 확인)` | DB 쪽이 접속을 받자마자 오류 없이 닫는다(주소가 다른 서비스를 가리키거나 DB 앞의 중계가 고장). 서버는 다시 접속을 1초에 다섯 번까지만 하고 그 요청을 바로 503으로 끝낸다(게스트로 계속). Neon 주소를 그대로 붙였는지(7단계), Neon 콘솔 · 장애 공지를 본다 |
| `서버: 처리되지 않은 비동기 오류 (…) — 판은 그대로 계속` | DB 드라이버 안쪽에서 처리되지 않은 오류가 났다(예: DB 쪽이 깨진 인증 응답을 보냄). 서버는 끝나지 않고 판은 그대로다. 가끔 한 줄이면 두고, 이어지면 괄호 속 이름과 함께 개발자에게 알린다 |
| `계정 DB 오류 … — DB 인증서 확인 실패 (sslmode 확인)` | Neon 주소면 생기지 않는다(공인 인증서) — 접속 문자열을 고쳤다면 다시 복사한다. 다른 DB로 옮겼다면 11절 ④ |
| `계정 DB 오류 … — DB 무료 한도 초과 (Neon 사용량 확인)` | Neon 콘솔의 사용량(Usage · Billing)에서 무엇을 넘었는지 본다. **compute 시간(월 100 CU-시간)**을 넘었으면 그달 남은 동안 compute가 멈춰 계정 요청이 모두 503 — **로그인한 사람도 게스트로만** 된다(판은 끝까지 그대로, 판 중 로그인한 사람의 그 판 보상은 '저장하지 못했어요'로 보일 수 있다). 다음 달 초에 풀리기를 기다리거나 유료로 올린다(11절 (가)). **저장 용량(0.5GB)**을 넘었으면 읽기는 되지만 쓰기가 실패한다(판 적립 · 접속 보상 · 의상이 '저장하지 못했어요', 첫 로그인의 기록 올리기 · 새 계정 만들기 실패) — 다음 달에 풀리지 않으니 유료로 올리거나(11절 (가)) 개발자에게 묻는다 |
| 한동안 아무도 쓰지 않은 뒤 첫 로그인 · 계정 읽기 · '계정에 저장하는 중…'이 몇 초 걸린다 | **정상**: 5분 쉬면 Neon compute가 잠들고, 다음 첫 요청에서 깨느라 보통 1초 안팎, 드물게 몇 초 늦다(무료는 끌 수 없다). 서버는 시도 하나 4.5초 · 한 번 더까지 합쳐 9초 안에 끝내고(넘으면 503), 화면은 12초까지 기다린다. Render 서버까지 잠들어 있었다면 그 깨우기(1분쯤)가 먼저다 |
| 친구 방 링크로 들어간 판이 계정이 아니라 이 기기 기록에 쌓였다 | 방 주소(친구 방 링크 · 마지막 방 복귀)로 연 경우는 계정 상태를 **3초까지만** 기다리고 방에 들어간다 — 그사이 Neon이 깨지 못하면 그 판은 게스트다(정상, 8단계 아래 메모). 잠든 뒤 첫 접속에서만 생긴다 |
| 저장 용량이 걱정된다 | 계정 하나는 행 하나(구글 고유 ID · 성장 기록 글)라 작다. Neon 콘솔의 사용량에서 0.5GB와 견준다. 넘으면 위 '한도 초과'의 저장 용량 갈래(쓰기만 실패, 다음 달에 풀리지 않음) |
| 실수로 지웠다 · 기록을 되돌리고 싶다 | **원칙적으로 되돌리지 않는다.** Neon의 복원(Restore)은 DB 전체를 그 시점으로 되돌려, 그 시점 뒤에 지운 계정까지 되살린다 — 처리방침은 계정 삭제 때 '바로 지운다'고 약속했고, 이메일이 없어 되살아난 행이 누구 것인지 알아 다시 지울 수도 없다. 그 밖에도 그 시점 뒤의 모든 사람 기록이 함께 돌아간다. 따로 백업 사본은 두지 않는다(사본은 처리방침에 없는 보관이 된다). 그래도 해야 한다면(6시간 안의 시점만 된다 — 무료 복원 기간) 먼저 개발자에게 묻고, 한 뒤에는 Neon이 되돌리기 전 상태를 남겨 둔 **백업 브랜치**가 생겼는지 콘솔의 브랜치(Branches) 목록에서 보고 지운다(남겨 두면 지운 기록이 그 브랜치에 남는다 — 확인 못 함, 화면 안내를 따른다) |

## 11. 유료 DB로 옮기기 (DB 주소만 바꾼다)

무료 한도(4단계 표)가 모자라거나 정식 운영을 키울 때. 서버는 표준 PostgreSQL 접속만 쓰므로 **코드는 바꾸지 않는다** — 바꾸는 것은 Render 환경 변수 `DATABASE_URL`(과 처리방침의 업체 · 기간 문구)뿐이다. 환경 변수를 저장하면 다시 배포되어 열린 방이 사라지므로 **아무도 없을 때** 한다.

> ⚠ **기록을 옮기지 않고 주소만 바꾸면 모든 사람이 새 계정이 된다.** 서버는 새 DB에 빈 `decoy_accounts` 표를 만들고, 로그인한 사람은 레벨 · 불씨 · 의상이 없는 새 계정으로 시작한다(그 기기에 남은 게스트 기록을 올릴 수 있을 뿐). 다른 곳으로 옮길 때는 반드시 아래 (나) ③으로 기록을 먼저 옮긴다

### (가) 같은 Neon에서 유료 요금제로 올리기 (주소 그대로)

1. Neon 콘솔 → **Billing**(요금) → 유료 요금제로 올린다(결제 수단은 사람이 넣는다). 프로젝트 · 접속 문자열 · 기록이 그대로라 **Render는 건드리지 않는다**
2. 요금제에 따라 **복원(PITR) 기간**이 6시간과 달라질 수 있다(설정에서 고르는 값일 수도 있다). 달라졌으면 처리방침 3 · 7 · 8번의 '최대 6시간'(7번은 Neon 표의 '목적 · 보유 기간')과 계정 삭제 페이지의 기간(`server/src/account/deletePage.ts`의 `ACCOUNT_BACKUP_RETENTION` — 코드 한 줄), 이 문서 4단계 표 · `docs/STORE_LISTING.md` 4장 메모를 같은 값으로 고쳐 달라고 개발자(또는 Claude)에게 부탁한다. 업체 · 나라가 같아 처리방침 6번 · 7번의 받는 자 · 나라와 Play 신고는 그대로다

### (나) 다른 곳으로 옮기기 (예: Render Postgres)

준비: 기록을 옮길 **PC 한 대**(태블릿만으로는 ③을 할 수 없다)와 PostgreSQL 클라이언트 프로그램(`pg_dump` · `psql`) 또는 Docker. **`pg_dump`는 옛 DB의 Postgres 판과 같거나 높은 판**을 쓴다(Neon 프로젝트 설정에 판이 보인다 — 예: 17이면 17 이상. 낮은 판의 `pg_dump`는 높은 판 DB를 읽지 않는다). 새 DB도 그 판 이상으로 만든다.

- ① **새 DB를 같은 싱가포르 지역에 만든다.** Render Postgres면 Render 대시보드 → **New** → **Postgres** → 지역 **Singapore**(웹 서비스 `decoy-web`과 같은 곳) · PostgreSQL 판(위 준비) · 유료 인스턴스 유형(무료 Render Postgres는 사용 기간 제한이 있어 계정 기록에 맞지 않는다 — DECISIONS 15절). 만든 뒤 그 DB 화면의 **Internal Database URL**(Render 안에서 쓰는 주소)과 **External Database URL**(PC에서 쓰는 주소)을 본다 — 둘 다 비밀번호가 들어 있다
- ② **로그인을 잠시 끈다**: Render → `decoy-web` → **Environment** → `DECOY_LOGIN` 값을 `0`으로 → **Save Changes**(다시 배포). 옮기는 동안 계정 기록이 바뀌지 않게 하려는 것이다 — 그동안 모두 게스트(이 기기 기록)로 플레이하고 판은 그대로다(로그인했던 기기에는 '지금은 로그인을 쓸 수 없어요'가 한 번 뜬다). Logs에 `계정 로그인: 꺼짐 (DECOY_LOGIN)`. 잠깐 끄는 것이라 Play 신고는 그대로 둔다
- ③ **PC에서 기록을 복사한다.** 주소는 꼭 큰따옴표로 감싸고(`?` · `&`가 들어 있다), 명령 기록 · 화면 공유 · 녹화에 남지 않게 주의한다(주소에 비밀번호가 들어 있다)
  - **옛 주소는 Neon의 직접 주소(풀러가 아닌 주소)를 쓴다**: Neon 콘솔 → **Connect** 창에서 **Connection pooling**을 끄면 호스트에 `-pooler`가 없는 접속 문자열이 나온다. Neon은 풀러 주소로 `pg_dump`를 하지 말라고 안내한다. Render에 넣어 둔 `DATABASE_URL`(풀러 주소일 수 있다)은 바꾸지 않는다 — 이 복사에만 쓴다

  ```bash
  # 1) 옛 DB(Neon 직접 주소 — 호스트에 -pooler 없음)에서 계정 표 하나를 파일로
  pg_dump --no-owner --no-acl -t decoy_accounts "옛 주소" > decoy_accounts.sql
  # 2) 새 DB(Render Postgres면 External Database URL)에 넣기
  psql "새 주소(외부 접속용)" -f decoy_accounts.sql
  # 3) 행 수가 같은지
  psql "옛 주소" -c "SELECT count(*) FROM decoy_accounts"
  psql "새 주소(외부 접속용)" -c "SELECT count(*) FROM decoy_accounts"
  ```

  - PostgreSQL을 설치하지 않고 Docker로(판 숫자는 위 준비대로): `docker run --rm -v "$PWD:/w" -w /w postgres:17 pg_dump --no-owner --no-acl -t decoy_accounts "옛 주소" -f decoy_accounts.sql`, 넣기는 같은 모양으로 `… postgres:17 psql "새 주소(외부 접속용)" -f decoy_accounts.sql`
  - 행 수가 다르거나 오류 줄이 많으면 ④로 가지 말고 개발자에게 묻는다(그동안 로그인은 꺼진 채로 둔다)
  - 다 끝나면 `decoy_accounts.sql` 파일을 지운다(계정 기록 사본 — 처리방침에 없는 보관이 된다)
- ④ **Render 환경 변수 `DATABASE_URL`을 새 주소로 바꾼다.** Render Postgres이고 웹 서비스와 같은 지역이면 **Internal Database URL**을 쓴다. 이 주소에는 `sslmode`가 없는데 그래도 된다 — 서버는 `sslmode`가 없으면 TLS를 먼저 시도하고, DB가 거절하면 (Render 내부망 안에서) 암호화 없이 잇는다(인증서 확인 없음 — 켤 때 Logs에 `계정 DB 연결: 인증서를 확인하지 않음 …` 경고가 찍히는 것이 맞고, 처리방침 10번 문구를 ⑥에서 맞춘다). 바깥 주소 · 다른 업체 주소면 `?sslmode=require`를 붙인 주소를 쓴다 — 서버가 TLS + **인증서 확인**까지 한다. 공인 인증서가 아닌(자체 인증 기관을 쓰는) DB면 `계정 DB 오류 … — DB 인증서 확인 실패 (sslmode 확인)`이 나온다: 그 업체가 주는 인증 기관(CA) 인증서 파일을 Render → `decoy-web` → **Environment**의 **Secret Files**에 올리고(서버 안에서는 `/etc/secrets/<파일 이름>`에 놓인다 — 확인 못 함, 화면 안내를 따른다) 주소 끝에 `&sslrootcert=/etc/secrets/<파일 이름>`(꼭 `/`로 시작하는 절대 경로)을 붙인다. 서버가 그 파일을 읽지 못하면 `계정 저장소를 만들지 못함 (DATABASE_URL 확인)`과 함께 로그인이 꺼진 채 뜬다(판은 그대로). 모르겠으면 개발자에게 묻는다
- ⑤ **다시 켠다**: `DECOY_LOGIN`을 `1`로 → **Save Changes**(④와 한 번에 저장해도 된다) → Logs에 `계정 로그인: 켜짐 (postgres)`가 있고 `계정 저장소 시작 실패` · `계정 DB 오류`가 없는지, `계정 DB 연결: …` 경고가 없는지(④에서 Render 내부 주소를 쓴 경우에만 나오는 것이 맞다) → 기존 계정으로 로그인해 **레벨 · 불씨 · 의상이 그대로인지** 확인한다. 모두 처음부터라면 기록이 옮겨지지 않은 것이다 — 바로 `DECOY_LOGIN`을 `0`으로 되돌리고 개발자에게 묻는다(그사이 새로 생긴 계정이 옮긴 기록과 부딪칠 수 있다)
- ⑥ **처리방침 · 신고 문서를 새 업체로 맞춘다** (코드 · 문서라 개발자(또는 Claude)에게 부탁한다): 처리방침 6번(위탁 업체) · 7번(국외 이전 — 받는 자 · 나라) · 3 · 7 · 8번(복원 기간 — 7번은 DB 표의 '목적 · 보유 기간') · 10번(DB 연결 암호화 · 인증서 확인 — ④에서 Internal 주소를 써 `계정 DB 연결: …` 경고가 찍힌다면) · 12번(개정 내용 · 시행일), 계정 삭제 페이지의 복원 기간(`ACCOUNT_BACKUP_RETENTION`), `docs/STORE_LISTING.md` 4장 메모 · 이 문서 4단계. **Play 데이터 보안 답은 그대로다** — DB 업체는 개발자 대신 저장만 하는 서비스 제공업체라 '공유'가 아니다(STORE_LISTING 4.3 '공유' 행). 처리방침이 배포된 뒤 6단계처럼 `/privacy`를 열어 확인한다
- ⑦ **옛 Neon 프로젝트를 지운다**: ⑤ 확인이 끝나면 Neon 콘솔 → 프로젝트 `decoy` → **Settings** → **Delete project**. 지워야 옛 계정 기록이 남지 않는다(미루면 그사이 계정을 지운 사람의 기록이 옛 DB에 남는다). Neon은 지운 프로젝트를 며칠 동안 되살릴 수 있게 남겨 둘 수 있다 — 지울 때 화면 안내(되살리기 기간)를 읽고 그 날짜를 진행 기록에 적는다. 그 기간이 지나야 옛 기록이 완전히 사라진다고 본다(확인 못 함). 그동안 옛 프로젝트를 되살리지 않는다
